## P1【技术缺陷】angle 衰减到 0 的终点，就是 v2 自己诊断过的"6rpm 常值旋转"

v3 第 4 条：无拟合时 `angle = angle × 0.7`（约 6 帧归零），并论证
"纯 P 环下偏航冲量 = Kp × angle₀ × 1/(1−0.7)，有界"。

**这个论证只约束暂态，不约束终态。** 衰减的终点是 angle=0，而在
`line_angle_target = −3.0`、死区 0.5° 的固件语义下（v2 §4 自己考证过）：

```
fW = (0 − (−3.0)) × 2.0 × (−1) = ∓6 rpm   ← 恒定旋转，每一拍都在
```

- "有界冲量"的说法对**持续信号**不成立：yaw 位移 = 6rpm × 时长，时长无界；
- 且正因为"无拟合"，没有任何反馈能停住这个旋转——车一边横移一边慢转，
  搜索轨迹是弧线不是直线；
- 讽刺的是：在 gyro_w=0 的现状下，**valid=0 反而是航向最安全的出口**
  （fWSum=0 → fAngleErr=0 → fW=0，纯横移不转头）。也就是说"无拟合"时
  正确的 fail-open 是尽快降 valid=0，而不是衰减到 0 还挂着 valid=1。
  v2 被批评"发 0 等于伪造对齐"，v3 改成"滑到 0"——终点状态是同一个错误。

可选修法（任一）：① 无拟合连续 K 帧 → 直接 valid=0 + state=4（推荐，最诚实）；
② 衰减目标改为"上一次拐角判据未命中时的 angle"（保持最后可信航向基准）；
③ 接受 6rpm 但在文档里如实标注为已知代价。

## P2【删过头】方向证据只冻结在出画前最后一眼，丢线期间没有任何复核手段

v3 删掉严格参考锁是对的，但把 **EMA 参考色也一起删了**——而上一轮批评的对象是
"一次性严格锁"，不是 EMA（EMA 只在有效帧更新、α=0.25、污染窗口只有几帧，
不存在严格锁的"锁不上/冻错"两个硬失败模式）。

后果：v3 的丢线方向完全来自**出画前最后一帧的行位置/趋势**，一旦出画原因是
撞击或弹跳（减速带正是这种场景），方向可能从第一帧起就是错的，而且在
"1.5s 时间盒 + Pi 找线预算(5+5s)"全程没有逐帧复核——车会朝错的方向满预算找完。
而丢线期间每帧画面"整幅是哪个面"这一新鲜证据本来就在手上（上下带还在算 margin），
EMA 参考色可以零成本提供逐帧复核。建议：方向主判据用 v3 的行趋势，
参考色 EMA 作为**复核/纠偏**保留（我的原始实现即是如此），二者不冲突。

## P3【欠约束】二次拟合外推取切线，没有 sanity 门槛

拐角命中后 `angle = 二次拟合在 x=160 处的切线`。问题：

- 0006 型帧的点聚在画面一侧（5~6 点全在右侧），向控制列外推的距离远超点云跨度，
  二次项在外推处放大噪声，切线可能给出狂野值——这比它要替换的"割线"更不稳定；
- 二次拟合对单个褶皱假点比线性敏感得多（一个假点弯掉整条曲线），
  追踪门批准后能挡住窗外假点，仍建议加一条**曲率上限 sanity**
  （如 |二次项| 超限或外推距离 > 点云跨度 × 1.5 → 退回割线或弃权）。

另：所谓"趋势"若只取上一帧的行差，±几像素的测量噪声就是同量级的"趋势"，
至少要两帧滑窗或死区。

## P4（小）col_profile 返回 (row,a,b,L) 在 v3 里已没有消费者

判向不用颜色了（§3）、身份门删了（§1 回应）、参考色删了（§2 回应）——
a/b 通道数据在 v3 里没有任何下游。要么删掉这条改动，要么结合 P2 把参考色复核
加回来（那时它才有意义）。

## P5（优先级）阶段二（删陀螺融合）建议比赛后再做

gyro_w=0×11 已证实陀螺条是死代码，删除的价值是"名实相符"（清理性质），
代价是：若 §6 排查后决定启用陀螺（例如逐站咬航向），得把删掉的代码加回来；
且 stage 2 触及 6 个固件文件 + map.c 11 行积木改写 + 地图 Tab 编辑界面变化。
方案自己都要求两阶段分开验——那就更没有理由在赛前挤进来。**建议：阶段一上车验证
通过、§6 排查清单拿到基线之后，再决定阶段二做不做。**

## 小结

| 项 | 性质 | 建议 |
|---|---|---|
| P1 衰减终点=6rpm 常值旋转 | 技术缺陷（自我矛盾） | 无拟合 K 帧 → valid=0+state=4，或改衰减目标 |
| P2 丢线期无方向复核 | 删过头（EMA 被连坐） | 行趋势为主 + EMA 参考色复核 |
| P3 二次拟合外推无 sanity | 欠约束 | 曲率上限 + 外推距离门槛 + 趋势死区 |
| P4 col_profile 无消费者 | 小 | 删或随 P2 恢复 |
| P5 阶段二时机 | 优先级 | 比赛后/排查后再做 |

v3 的框架（时间盒 + state + 定向找线 + 拐角切线 + 追踪门）与我们的实现已同构，
P1~P3 修掉后，阶段一可以放心上车；§6 排查清单（摆车逐站读 ang）建议最先执行，
它不需要改任何代码，还能顺便回答"越来越偏"到底是不是支架被减速带撞松。
