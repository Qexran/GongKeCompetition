## 0. 背景与动机（简述）

现状打靶链 = `STEP_TARGET_ALIGN_WAIT`（车横移摆正）→ 连排 2~3 块 `STEP_TARGET_CALIB_WAIT`
（发 "6" 全画面识别 8 帧投票 → 按二维码第二位选靶 → Δpx×比例尺 → 舵机6/3 开环增量走一步）
→ `STEP_LASER_SHOOT`。

随机偏（有时正中、有时三环）的病根不在检测（离线 61 用例中位 0.26mm / p95 0.59mm，
判据 10 环半径 7.5mm），而在**开环执行链**：

1. 比例尺线性近似只在标定位姿附近成立，首轮大修正（≤±20°）落在非线性区，且步数有限时停在半收敛位**不报错**；
2. 舵机回差：每轮修正方向可能反转，"指令到位 ≠ 实际到位"，最终落在哪取决于最后一次逼近方向 —— 方向随机的典型症状；
3. 相机-激光视差烤死在 `tg_center_x/y` 一个固定瞄准点里，姿态变化 → 残余系统误差跟着变；
4. 每轮 "6" 重开摄像头（15 帧预热 + AWB）+ 8×220ms 采帧 + 1s S 曲线，单轮 ~4-5s，链路长、变量多。

**新方案**：识别一次锁定目标后，Pi 在小跟踪窗内高频（目标 ≥20Hz）回传靶心，
MCU 以 ~10Hz 控制节拍做比例闭环微调舵机6/3，残差每拍都测、每拍都补 ——
1/2 两条被根治（回差表现为死区，环会持续推过去；比例尺失准只影响收敛速度不影响终点），
3 缓解（收敛姿态每次一致，残余视差变成常数偏移，标一次 `tg_center` 长期有效）。

**共存原则：老方案一行不动。** 命令 "6"、`0x04` 帧、`STEP_TARGET_CALIB_WAIT`、
`ucRpiTargetAlign` 全部保持原样；两套可在同一条路线里混排。

## 1. 总体架构

```
        ① STEP_TARGET_SCAN_WAIT（可选，锁定/预检积木）
MCU ──── "6" ────────────────────────────► Pi  run_target_detect（现有，不动）
MCU ◄─── 0x04 结果帧（现有，不动）────────── Pi

        ② STEP_TARGET_SERVO_WAIT（新，流控闭环积木）
MCU ──── "7" 起流 ──────────────────────► Pi  _target_stream 线程（新）
MCU ◄─── 0x05 流帧 ~20Hz（新）───────────── Pi  小窗跟踪 + 门控 + 鲁棒拟合
MCU: 10Hz P 环 → 舵机6/3 小步 S 曲线；收敛/超时/行程超限
MCU ──── "8" 停流 ──────────────────────► Pi  线程退出、释放相机

        ③ 终验（可选）= 现有 STEP_TARGET_CALIB_WAIT（识别+死区判断+按需终补一步）
        ④ STEP_LASER_SHOOT（现有，不动）
```

职责划分（沿用项目一贯哲学 **"Pi 不掺和任务语义"**）：
- **Pi 只发测量**：流帧回传跟踪窗内找到的所有靶（≤3 颗、带颜色、全分辨率坐标）。
  哪颗是目标由 MCU 按二维码第二位挑 —— 与 0x04 帧同构。
- **MCU 做闭环**：比例尺/方向/瞄准点全在 MCU 的 Beam 运行时量里
  （`tg_px_to_deg_x/y` 就是现成的 Kp，`tg_x/y_sign` 就是方向），
  因此**新方案第一天就能继承今天标好的全部 `tg_*` 标定**，且天然做成蓝牙可调。

## 2. 协议契约（双端同步改动）

### 2.1 新命令（TYPE_CMD 的 ASCII payload）

| 命令码 | 语义 | Pi 端行为 |
|---|---|---|
| `"7"` | 靶标流起流 | 独立线程启动 `run_target_stream`（**不同步阻塞主循环**，心跳照发） |
| `"8"` | 靶标流停流 | 置 abort → 线程释放相机退出；未在跑时幂等（打 WARN 即可） |

Pi 端 `handler.py::_COMMANDS` 里 `"7"`/`"8"` 空闲，直接追加。
MCU 端 `emRpiTaskTdf` 追加两个枚举值 + `s_apcTaskCmd[]` 追加两行（见 §4.1）。

### 2.2 新帧：靶标流帧（TYPE_COORD，Pi → MCU，~20Hz）

```
DATA = [TAG=0x05][status u8][count u8]
       + count × [color u8][cx u16 LE][cy u16 LE][r u16 LE]
LEN  = 3 + 7×count            （count ≤ 3 → 最长 24B < FRAME_MAX_LEN=64）
```

| 字段 | 说明 |
|---|---|
| `TAG=0x05` | 与 0x01 巡线 / 0x02 人质 / 0x03 色球 / 0x04 靶标同族 |
| `status` | 流模式下恒 `1`（检测正常运行）。预留，MCU 不消费 |
| `count` | 本帧在跟踪窗内找到的靶数。**`count=0` 表示"流还活着但没找到"**（丢目标），不是失败帧 |
| `color` | `1`红 / `2`绿 / `3`蓝；**`0xFF` = 无色模式**（Pi 端 `TARGET_STREAM_USE_COLOR=0` 时颜色未知，见 §3.4） |
| `cx/cy` | 靶心像素，**全分辨率 1920×1080**（与 0x04 帧同口径，`tg_*` 标定直接复用） |
| `r` | 外圆等效半径 [px]（与 0x04 帧同口径，已按 Ø55/Ø100 折算） |

按 `cx` 升序（与 0x04 帧同约定）。

**为什么复用 0x04 的布局而不另造格式**：MCU 解析代码可整段照抄
`vRpiTask` 里 0x04 分支；坐标/半径语义一致，固件侧无任何换算。

字节示例（count=2，绿靶 + 蓝靶）：

```
05 01 02  02 3E 03 1C 02 3A 00  03 FA 05 1B 02 39 00
TAG st n  G  cx=830 cy=540 r=58  B  cx=1530 cy=539 r=57
```

空窗帧（丢目标，流仍活）：`05 01 00`。

**带宽核算**：最坏 24B DATA + 5B 帧头 = 29B × 25Hz ≈ 725 B/s，115200 波特（~11.5 kB/s）富余。

### 2.3 与既有帧的互斥规则（照抄巡线的老规矩）

- Pi 端收到 `"1"/"4"/"5"/"6"/"end"/"r"` 时**先停靶标流**（结果帧与流帧同为 COORD，防交错；
  同时这些任务也要用主摄）。对称地，`"2"`（巡线起流）也要先停靶标流，`"7"` 要先停巡线
  （两条流独占主摄 + COORD 通道）。
- MCU 端：`ucRpiWaitTargetResult` 只认 0x04，**0x05 走独立 Beam 快照**（§4.2），
  互不误抓 —— 但前提是 0x05 分支必须放在通用 `ucDataLen >= 9` 分支**之前**（§4.3，硬性）。

### 3.2 新文件 `tasks/_target_stream.py`

结构上照抄 `_line.py` 的线程/退出/异常模式，算法上复用 `_target.py` 的全部几何件：

```python
# 从 _target.py 导入复用（同包内私有函数直接 import 是可以的, 但更稳的做法是
# 在 _target.py 里给这几个加公开别名, 避免日后重构改名时静默断链）:
from tasks._target import (
    _detect_frame,        # 全画面单帧检测(锁定阶段用, 含跨色一致性+兜底)
    _color_candidates,    # 单色候选枚举(bbox 局部轮廓树, 2026-09 性能版)
    _locate_one,          # 候选 → (cx,cy,r_outer_equiv), 内边界优先外边界兜底
    _open_with_retry,     # 主摄打开重试(先让 Web 推流释放设备)
)
```

主循环骨架：

```python
AIM_TAG = 0x05
COLOR_UNKNOWN = 0xFF     # 无色模式哨兵, 单片机按"离瞄准点最近"退化选靶

def _build_stream_frame(targets):
    data = struct.pack("<BBB", AIM_TAG, 1, len(targets))
    for t in targets:
        data += struct.pack("<BHHH", t["color"], _clamp_u16(t["cx"]),
                            _clamp_u16(t["cy"]), _clamp_u16(t["r"]))
    return data

def run_target_stream(abort_event=None):
    cap = _open_with_retry(abort_event)          # 打开一次, 整个流期间保持
    if cap is None: 发一帧 count=0 后 return      # 让 MCU 立刻知道起流失败
    try:
        # ---- 阶段1: 锁定(全画面) ----
        # 连续 TARGET_STREAM_INIT_FRAMES 帧跑 _detect_frame(全帧, cfg 同 run_target_detect
        # 的 cfg 字典, 但 use_roi 强制 False —— 锁定阶段要看全画面);
        # 每色取出现≥2次的中位位置作为该色跟踪初值(tracked[color] = {cx, cy, r})。
        # 锁不到: 不退出 —— 每隔 5 帧重试一次全画面, 期间照发 count=0 帧
        # (MCU 靠帧计数判新鲜度, count=0 只是"没目标", 流本身活着)。

        # ---- 阶段2: 跟踪(小窗) ----
        while not abort and time.time()-t0 < config.TARGET_STREAM_MAX_S:
            frame = CameraManager.read(cap, ...)
            # 窗 = ∪ 各 tracked 目标位置 ± margin_eff 的 bbox, clamp 到画面;
            # margin_eff = MARGIN_PX × (1 + 该目标连续丢失帧数), 封顶半幅
            # → 丢失越久窗越大, 自然退化成全画面重搜
            x0,y0,sub = crop(frame, window)
            hsv = cv2.cvtColor(sub, cv2.COLOR_BGR2HSV)   # 小窗内只转一次

            if config.TARGET_STREAM_USE_COLOR:
                for color in list(tracked):              # 带色模式: 逐跟踪色
                    cands = _color_candidates(hsv, color, min_area, sat_min, val_min, families[color])
                    # 门控: ① 距离门 —— 离上一帧位置最近的候选(窗本身就是位置门的粗版)
                    #       ② 半径门 —— r ∈ last_r×(1±R_TOL)
                    pick = 门控后的候选
                    if pick:
                        cx, cy, r = _locate_one(pick)     # 注意 +x0,+y0 加回全帧坐标
                        tracked[color] = 更新(直接替换, 不平滑 —— MCU 端自己滤波)
                        lost[color] = 0
                    else:
                        lost[color] += 1                  # 位置冻结不动, 窗下一帧扩张
                targets = [{color,cx,cy,r} for 每个跟踪色]  # 丢失的颜色本帧不回传
            else:
                # 无色模式: 单跟踪器。掩膜只按 S≥sat_min & V≥val_min(无色相),
                # _color_candidates 的"色相族"换成整段 0~180;
                # 门控同上(距离+半径, 半径基准 = 锁定阶段的初值);
                # 回传单颗, color = 0xFF。
                # ⚠ 已知风险(接受才用): 另外两颗靶是等大圆环, 无色时唯一区分是
                #   距离门 —— 一次大修正跳到邻靶就锁错。所以默认 USE_COLOR=1。

            serial_comm.send_frame(TYPE_COORD, _build_stream_frame(sorted(targets, key=cx)))
            # 1Hz: print(f"[靶标流] fps={..} n={len(targets)} 窗={w}x{h} 丢={丢色列表}")
            #      + cv2.imwrite(TARGET_STREAM_LAST_FRAME_PATH, 标注帧)   # Web 预览
            time.sleep(按 TARGET_STREAM_HZ 限流的剩余时间)
    except SerialDisconnected:
        pass                                             # 退出, 相机在 finally 释放
    finally:
        CameraManager.release(cap)
```

实现要点（写代码时别丢）：

- **坐标回加**：`_color_candidates`/`_locate_one` 的返回都是「传入图像」坐标系，
  裁切后必须 `+x0, +y0` 还原全帧坐标（`run_target_detect` 的 ROI 路径已有同款代码可抄）。
- **参数每帧从 config 现取**（`import config` 后 `config.TARGET_STREAM_*`），
  不能 `from config import ...` 拿导入时快照 —— Web 改了要立即生效（`_line.py` 同款约定）。
- **min_area 沿用 `TARGET_MIN_AREA`、S/V 沿用 `TARGET_SAT/VAL_MIN`、色相族沿用
  `COLOR_HUE_FAMILIES`** —— 不另开阈值来源（"什么算红"只留一个出处）。
- 锁定阶段 cfg 直接照抄 `run_target_detect` 里那个 dict，别手搓第二份。
- 帧处理异常单帧吞掉（照抄 `run_target_detect` 的 try/except + WARN），别让一帧坏图杀线程。
- 函数命名：打包函数叫 `build_stream_frame`（**不能**叫 `build_result_frame`/`build_target_frame`，
  `tasks/__init__.py` 再导出会互相覆盖 —— 那两个坑的注释就是这么来的）。

### 3.4 颜色开关的语义（用户决策 ②）

- 开关只存在于 **Pi 端**（`TARGET_STREAM_USE_COLOR`，Web 可调）——
  "怎么检测"是 Pi 的实现细节，MCU 不掺和，协议不用带参。
- 帧里的表现：带色模式回传真实 `color`（1/2/3）；无色模式回传 `color=0xFF`。
- **MCU 端退化规则**（自动，无需配置）：先找 `color==二维码目标色` 的靶；
  没有但存在 `color==0xFF` 的靶 → 取**离瞄准点 `(tg_center_x, tg_center_y)` 最近**的一颗
  （闭环本来就把靶往瞄准点拉，最近的那颗就是正在跟的那颗）。
- 无色模式的已知代价（写进 config 注释，默认 `USE_COLOR=1`）：
  另外两颗靶是**等大的圆环**，无色时唯一区分手段是距离门，一次大修正跳到邻靶就锁错；
  蓝柜子等大块彩色背景会被 S/V 掩膜抓进候选，靠半径门 + 距离门 + 窗挡住。

### 4.1 app_rpi.h

```c
/* 靶标流帧（Pi tasks/_target_stream.py, docs/串口协议.md §6f）: DATA = [TAG=0x05]
 *        [status u8][count u8] + count×[color u8][cx u16 LE][cy u16 LE][r u16 LE],
 *        共 3+7×count B —— 与 0x04 靶标帧同布局, 区别只在它是 ~20Hz 连续流。
 *        count=0 = 本帧没找到(流还活着); color=0xFF = Pi 无色模式(颜色未知)。 */
#define RPI_AIM_TAG         0x05u
#define RPI_AIM_HDR_LEN     3u
#define RPI_AIM_TGT_LEN     7u
#define RPI_AIM_MAX_CNT     3u
#define RPI_AIM_COLOR_UNKNOWN 0xFFu   /* Pi 端 TARGET_STREAM_USE_COLOR=0 时的哨兵 */
```

任务枚举追加（`s_apcTaskCmd[]` 同步追加两行）：

```c

    RPI_TASK_AIM_STOP    = 12,  /* "8"  靶标流跟踪停止 */
```

公开 API 追加：

```c

    * 发"7"起流 → 按二维码第二位选靶 → 每拍按偏差微调舵机6/3(共用 tg_* 标定) →
    * 收敛(ts_conv_px×ts_conv_ticks)/超时/累计行程超限 → 发"8"停流。仅任务上下文调用 */
```

### 4.2 app_beam.h / app_beam.c —— 流帧快照 + ts_* 参数组

**(a) 命令表** `s_apcTaskCmd[]` 追加 `"7"`/`"8"` 两行（与枚举对齐）。

**(b) vRpiTask 的 COORD 分发**，两处改动：

1. **诊断行排除 0x05**（现有 `if (ucDataLen >= 15u)` 的 COORD 调试行）：

```c

{
    /* 靶标流帧: 与 0x04 帧同布局, 差别只在高频连续 → 走独立快照+帧计数(同巡线帧),
     * 不置 ready、不进 last packet。count=0(丢目标)照常推进帧计数。 */
```

**(c) 闭环原语 `ucRpiTargetServo(ulTimeoutMs)`**（放在 `vTargetCalibAim` 后面，同族）：

```c
uint8_t ucRpiTargetServo(uint32_t ulTimeoutMs)
{
    /* ① 二维码校验 —— 与 vTargetCalibAim 完全同款:
     *    iQr<0 → 长鸣返回; ucWant=(iQr/10)%10 ∉1..3 → 长鸣返回。 */
    /* ② 进门快照标定(局部量, 免得算到一半被蓝牙改):
     *    centerX/Y = fGetTgCenterX/Y();  swap = ucGetTgXySwap();
     *    scaleX/Y, signX/Y = fGetTgPxToDeg*, fGetTg*Sign();   ← 共用 tg_*
     *    kp = fGetTsKpScale(); stepMax = fGetTsStepDeg(); convPx = fGetTsConvPx();
     *    convTicks, ctrlMs, moveMs, staleMs, travelMax = ts_* 其余; */
    /* ③ 轴映射(照抄 vArmAimByPixels 的语义): swap=0 → X路=舵机6/scaleX/signX, Y路=舵机3/...;
     *    swap=1 → 两路(舵机+比例尺)整套对调, 方向符号不跟着翻。 */
    /* ④ vArmSeqAbort();  ← 首次动舵机前掐后台臂序列(同 vArmAimByPixels) */
    /* ⑤ vRpiSendTaskCmd(RPI_TASK_AIM_START); */
    /* ⑥ 闭环(ulElapsed < ulTimeoutMs):
     *     vTaskDelay(ctrlMs);
     *     新鲜度: ulGetAimFrameCount() 变了 → 刷新 tick; 停涨 > staleMs →
     *             convCnt=0, 本拍不动舵机, continue(冻结而非放弃, Pi 回来即恢复; 见 app_line.c 同款);
     *     vGetAimFrame(&cnt, astT);
     *     选靶: ① color==ucWant; ② 否则 color==RPI_AIM_COLOR_UNKNOWN 里离(centerX,Y)最近的一颗;
     *           都没有 → convCnt=0, continue(count=0 丢目标帧, 流还活着);
     *     dx = cx−centerX; dy = cy−centerY;
     *     |dx|<convPx && |dy|<convPx → convCnt++; 达到 convTicks → ucOk=1, break;
     *     否则 convCnt=0;
     *     stepX = dx×scaleX×kp×signX, stepY = dy×scaleY×kp×signY;  各钳 ±stepMax;
     *     travelX += |stepX|, travelY += |stepY|;  任一 > travelMax →
     *             vRpiSendDebug("TGTS fail: travel"); 长鸣; 走 ⑦ 的停流后 return 0;
     *     读舵机当前角(c_pstGetServoDeviceParam()->stRunningParam.fCurrentValue),
     *     目标角=当前+step, 钳静态量程(照抄 vArmAimByPixels);
     *     vServoSetTargetValueTimed(devX, angX, moveMs); ×2;
     *     —— 不阻塞等到位: 节拍本身就是定步长的推进器(与 vArmAimByPixels 的
     *        "settle-wait"不同, 这是连续闭环)。 */
    /* ⑦ 无论成败: vRpiSendTaskCmd(RPI_TASK_AIM_STOP);   ← 放唯一出口, 超时/行程/成功都停流 */
    /* ⑧ 蜂鸣+调试串: 成功=50/50×2 + "TGTS ok: dx=?dy=?px n=?拍";
     *    超时=200 长鸣×1 + "TGTS fail: timeout"(把当时的 dx/dy 也打出来, 现场排障第一手); */
}
```

设计说明（写进函数头注释）：

- **P 环 + 三道阻尼**（单拍限幅 `ts_step_deg`、收敛阈值 `ts_conv_px`、连续拍数
  `ts_conv_ticks`），**刻意不做 I/D**：靶静止、无负载扰动，P 到死区即收敛；
  迟延链 ~150-200ms（采集+处理+串口+节拍），Kp 直接沿用 0.04°/px 起步，
  振荡就降 `ts_kp_scale`，不动共用的 `tg_px_to_deg_*`。
- **行程闸是安全夹不是精度旋钮**（对应老方案 `TARGET_MAX_STEP_DEG` 的教训）：
  闭环被误检带飞时会"越纠越偏"，累计 ±25° 一到就长鸣放弃，代价限制在已知范围内。
- **动停测模式（第一版推荐）**：`ts_ctrl_ms=100` + `ts_move_ms=100` 天然就是
  "走 100ms → 停 → 下一拍拿新帧"，回避运动模糊；要更快可把 move 降到期 60~80ms。
  车/靶全程静止，速度不敏感，**精度优先**。
- Pi 起流后要先做 1~3 帧全画面锁定（~0.5-1s）才有流帧，超时默认 6000ms 足够覆盖
  "起流 1s + 收敛 1-2s + 余量"。**这个值没有 <8s 的硬约束**（流模式下 Pi 心跳照发，
  不像阻塞命令那样断心跳），但别配太大，路线节奏会拖沓。

### 4.4 app_config.h 新段（插在「标靶对位」段之后、「底盘脉冲系数」段之前）

⚠️ 两条硬规矩（CLAUDE.md 记载的现场踩坑）：
- **段头必须单行** `/* ==== 名字 ==== */` 形式（`tuning.py::RE_SECTION` 只认单行，
  写成多行块注释整段参数会被静默归进上一段）；
- **尾注释按调参 DSL 写**（`/* 显示名 [单位] @(范围) // 备注 */`），否则「调参」Tab
  拿不到元数据；数值类型由值本身推断（`2.0f`/`100u`），别往 DSL 里塞类型。

```c

/* 链路（脚本步骤 STEP_TARGET_SERVO_WAIT → ucRpiTargetServo）:
 *   发 "7" 起流 → Pi 在小跟踪窗内 ~20Hz 回传 TAG=0x05 流帧(靶心+半径, 全分辨率)
 *   → 本端 10Hz 节拍做 P 闭环: Δ=靶心−瞄准点 → ×tg比例尺×ts_kp_scale → 钳单拍上限
 *   → 舵机6/3 小步 S 曲线 → 连续 ts_conv_ticks 拍进死区判收敛 → 发 "8" 停流。
 *   与「标靶校准」(STEP_TARGET_CALIB_WAIT, 开环迭代) 是并存的两个方案。
 * ⚠️ 瞄准点/比例尺/方向/XY对调**共用 TARGET_**(tg_*)那一套 —— 同一套物理标定;
 *    本段只管闭环节拍类参数。断电回本段宏 = 上电默认; 运时量=蓝牙「标靶流控」组(ts_*)。 */
#define TARGET_SERVO_CTRL_MS     100u     /* 控制节拍 [ms] @(20~500) // 闭环每拍间隔; 配合 MOVE_MS 即"动-停-测"节拍 */
#define TARGET_SERVO_MOVE_MS     100u     /* 单拍S曲线时长 [ms] @(20~1000) // 每拍小步的 S 曲线时长; 会被全臂速度闸削峰 */
#define TARGET_SERVO_STEP_DEG    2.0f     /* 单拍修正上限 [°] @(0.1~20) // 0.04°/px 下 2°≈50px; 振荡先降 KP_SCALE 再降它 */
#define TARGET_SERVO_CONV_PX     4.0f     /* 收敛阈值 [px] @(0~100) // 两轴偏差均低于此值算"在靶"; 检测噪声地板≈0.3px, 4px 很安全 */
#define TARGET_SERVO_CONV_TICKS  5u       /* 收敛拍数 @(1~50) // 连续 N 拍在靶才判收敛(100ms×5=0.5s, 抗单帧抖动) */
#define TARGET_SERVO_TRAVEL_DEG  25.0f    /* 单轴累计行程上限 [°] @(1~90) // 安全夹: 闭环被误检带飞时到此为止(长鸣放弃), 对应老方案 MAX_STEP 的教训 */
#define TARGET_SERVO_STALE_MS    400u     /* 帧新鲜度阈值 [ms] @(50~2000) // 流帧计数停涨超此值=Pi掉线/停发, 冻结不动舵机(非放弃, 恢复即续跑) */
#define TARGET_SERVO_KP_SCALE    1.0f     /* 增益系数 @(0.1~2) // ×tg_px_to_deg_x/y 的总增益; 振荡降它, 不动共用标定; 运行中改会变控制律 */
```

## 6. 风险与对策（新方案自己的坑）

| 风险 | 对策 | 落点 |
|---|---|---|
| **运动模糊**：舵机动着采帧, 拟合飘 | 第一版"动-停-测"节拍(ctrl=move=100ms); 半径门剔坏帧; 实测不够再把 move 降到 60~80ms | ts_ctrl/move_ms, Pi R_TOL |
| **误锁/跳靶**：大修正时跟丢或跳到邻靶 | 带色模式(默认)颜色即防误锁; 距离门+半径门; 累计行程闸 ±25° 兜底 | Pi 门控 + ts_travel_deg |
| **环内振荡**：迟延 ~200ms + Kp 偏大 | 单拍限幅 2°; 死区 4px; 连续 5 拍判收敛; 振荡降 ts_kp_scale | ts_step/conv/kp_scale |
| **AE/AWB 漂移**：自动曝光下长跑掩膜失锁 | 印刷色 SAT_MIN=65 余量本就紧; 若台架复现, 打靶档切手动曝光(CAM_MAIN_AUTO_EXPOSURE=1, camera.py 档位机制现成) | config CAM_MAIN_* |
| **窗跟丢**(目标出窗) | 窗随目标走 + 丢失逐帧扩张(封顶全幅); 丢目标发 count=0, MCU 冻结不瞎修 | Pi margin 策略 |
| **流帧与结果帧交错** | 分发按 TAG 区分 + Pi 端互斥规则(§2.3) | 双端 |
| **调试串刷爆** | COORD 诊断行排除 0x05(§4.3b-1) | app_rpi.c |
| **相机争用**(Web 推流/识别任务) | 起流先 `_stop_main_stream()`; "1/4/5/6/end/r" 先停流 | handler.py |
| **帧率不达标**(<20Hz) | 先实测(`test_camera.py --no-preview` + 流日志 fps 行); 帧率不够时闭环按实际跑 —— 10Hz 控制 + 4px 死区对 15Hz 依然工作, 只是收敛慢一点 | Pi 日志定标 |

**精度上限（诚实预期）**：闭环能消掉执行链随机性，落点下限由两件事决定 ——
`tg_center` 标定（视差烤在里面，距离固定则稳定）和舵机本身的角分辨率/重复精度
（7.5mm 10 环 @~1m ≈ 0.43°，指令步 0.08° 没问题，回差靠环推过去）。
合理预期：稳定 1 环以内；能否钉 10 环看标定与舵机。若终验后发现**固定方向**的残余偏差，
下一步做「同向逼近」：终补那一步故意从固定方向进（先过头 1° 再回来）把回差吃掉 —— 本期不做。

## 8. 明确不做的事
