# 巡线算法分析与实施方案

> 项目：GKS 工科赛 · 侧装 OpenMV 巡线（OpenMV → 树莓派 → 单片机 三端链路）
> 文档整理：2026-09-23，涵盖两轮算法升级、单片机航向环诊断与性能优化现状。

---

## 0. 系统链路与职责

```
OpenMV (E:\main.py)          树莓派 (GKS_Competition)           单片机 (GongKeCompetition)
  采样 320x240, 固定曝光        openmv_serial.py  读+缓存           app_rpi.c  巡线收敛积木
  逐列找交界 → 拟合      --串口-->  tasks/_line.py  归一化+PID   --串口-->  app_line.c  vLineFollowConverge
  输出 offset/angle/valid/state         定向找线策略                    位置环(steer→vx) + 航向环(angle+陀螺融合)
```

- 帧格式（2026-09 扩展，向后兼容）：`L,<offset>,<angle>,<valid>,<state>\r\n` @115200
- 关键事实：**单片机在 valid=0 时也执行 steer**（app_line.c），只有航向环在丢线时切陀螺。
  所以"丢线车不动"的根因不在 valid 位，而在丢线期 steer 的大小与方向。

## 2. 第一轮：丢线方向分类 + 定向找线

### 2.1 state 编码（帧第 5 字段）

```
0 = 正常直线测量
1 = 有效但交界是曲线（路口/弯道，已用近半段重拟合）
2 = 丢线：边界远出画面上方（车偏进路里 → 该向边界横移）
3 = 丢线：压到边界区/黄区（该向路内横移）
4 = 丢线：方向不明（没参考色 / 点和颜色都说不清）
```

### 2.2 两级分类（OpenMV，只在丢线帧跑）

- **① 零星交界点**（不足拟合的 6 个，如只剩右上角一段）：看点的中位行。
  `<155` 行 → state 2；`>175` 行 → state 3；中间 → 交给②。
- **② 颜色身份**（一个点都没有）：每帧有效时把上/下带色心 EMA 记为参考色
  （`ref_bnd` 边界区 / `ref_road` 路面），丢线帧拿上、下带各自的 (a,b) 色度距离投票，
  两带一致且距离 ≤ `LOST_CLASS_GATE` 才下结论，否则 state 4。
- **实测依据**（练习地图 7 张照片）：两面色心距离 ≈65；压黄区整帧到黄区参考仅 ≈10，
  到路面参考 35.7 → 门槛 25 有两倍余量。只比 a/b 不比 L（阴影主要动亮度）。

### 2.3 Pi 端定向找线（tasks/_line.py）

- `_toward_steer()`：向边界横移的 steer 符号由
  `LINE_ERR_SIGN × ((-100 − LINE_SETPOINT)/100)` 的符号推出，与 PID 误差同一条标定链。
  改 `LINE_ERR_SIGN` 找线方向自动跟随，**不再死写**。
- 丢线分两路：
  - **方向明确（state=2/3）**：静默 `LINE_LOST_CONFIRM_S`（0.4s，躲单帧毛刺，
    期间沿用丢线前正在执行的 steer）→ 按 state 定向找线，大小 = `|LINE_SEARCH_STEER|`。
  - **方向不明（state=4/旧固件）**：旧三段（保持 → 固定方向兜底 → 停），
    只有这条兜底路径里 `LINE_SEARCH_STEER` 的符号还参与。
  - 两路都受 `HOLD_S + SEARCH_S` 总预算封顶，超时停（防跑飞）。
- 与旧死写值的一致性：现配置（ERR_SIGN=-1, SETPOINT=20）下 state=3 → steer=-0.5，
  与旧 `LINE_SEARCH_STEER=-0.5` 完全一致；state=2 → +0.5（新增的另一半）。

### 2.4 路口/过减速带纠偏（state=1）

- 拟合残差 RMS > `CURVE_RMS_PX`（5.0）→ 判曲线；
- 取全局拟合内点中**行 >160 的近半段**（≥4 点且更直才采用）重拟合 ——
  航向跟"车马上要进的这段"的切线，而非整条弧的平均切线；
- 控制列求出的交界行**夹回测量窗 [80,240]**，防近段切线外推甩出虚大满偏；
- 之后交给现有链路：满偏 → Pi 的 `|err|≥1` 定速横移；完全出画 → state=2/3 定向找线；
  回到正常区 → PID + 单片机航向环自动接管。**过减速带落地后的随机车头 =
  "先横移回视野、再由角度环转正"。**

### 2.5 部署兼容性

- Pi 解析器接受 4 或 5 字段（旧 OpenMV 固件也能跑，state 缺省 0）。
- **部署顺序必须先 Pi 后 OpenMV**（旧 Pi 会把 5 字段帧整行拒收 → 假死）。
- 单片机无需改动（valid=0 照执行 steer，正好承接定向找线）。

## 3. 第二轮：跳变与褶皱对策（OpenMV）

实车症状：① 黄区→灰区过渡时斜率跳变；② 路口/灰地图上褶皱产生假交界点
（实拍假点离真线 80~120px）。四道对策，全部只动"选点/出量"，不动拟合核心，
每一道都带兜底（门杀过头自动退回旧行为，不会全拦死→误报丢线）：

| 对策 | 参数 | 说明 |
|---|---|---|
| ① 判别通道滞回 | `CH_HYST=1.3` | 换通道要 1.3 倍优势。过渡区 a/b 分离度接近，逐帧取优会在两通道间抖 → 交界行整列跳 |
| ② 追踪门 | `TRACK_GATE_PX=35`, `TRACK_GATE_T=0.3` | 与上一有效帧拟合线偏差超它的穿越不认（假点 80~120px 一抓一个准；无轨迹/超 0.3s 不设门） |
| ③ 颜色身份门 | 复用 EMA 参考色 | 穿越上侧须像边界区色、下侧须像路面色（取样取 j-1/j+2 避开交界污染）。褶皱/换色缝这类"同侧内伤"两侧同色，必错一边 |
| ④ 航向角限速 | `ANGLE_SLEW=120`（0.1°/帧） | 12°/帧≈190°/s，真车到不了；任何残余跳变挡在输出端，大台阶摊成两三帧斜坡 |

选点结构：每列产出"门后点"与"兜底点"两个集合 →
门后点 ≥6 用净的；<6 但兜底 ≥6 退回旧行为（RANSAC 自己抗）；都 <6 取多的一边。

## 4. 单片机巡线收敛"越来越偏、越来越不灵敏"（已诊断，待定方案）

### 4.1 根因

航向环两条误差（app_line.c）：

- 相机条：`图像角 − line_angle_target`（跟当前线，永远新鲜）；
- 陀螺条：`line_gyro_target − yaw`（**绝对世界航向**，零点=开机朝向）。

`ucRpiLineConverge(..., fGyroTarget)`（app_rpi.c:483）每步积木把**写死的陀螺目标**写入一次。
于是陀螺条 = "死的数" 对 "活的量"：

1. **MEMS yaw 单调漂移**（上电头几分钟最快）；
2. **减速带撞击 + 弧线打滑**造成的目标外真实航向变化，死目标不知道；
3. 脚本里的目标值是按上一场/上一段漂移状态标出来的，失效方向一致 → **越比越偏**。

### 4.2 为什么同时"不灵敏"

- 两条误差反号互相**抵消** → 加权平均变小（不灵敏）而车停在折中航向（偏）；
  即代码注释里的"cam 与 gy 异号 → 权重 50 左右车反而变迟钝"；
- 陈旧误差大 → 输出顶 `±LINE_W_MAX` 限幅（饱和不响应）；
- 抵消后的误差落进 `LINE_ANGLE_DEADBAND_DEG` 死区（完全不修正）。

### 4.3 车上验证三步

1. 看步末 `LINE mix: w=.. cam=.. gy=..`：迟钝时刻 cam/gy **异号** = 实锤陀螺打架；
2. 同一直线段、车摆平行，比赛早期 vs 晚期各读一次 OLED `ATK-Yaw`，差值即累积漂移；
3. 晚期蓝牙把 `line_gyro_w` 改 0（纯相机），恢复灵敏即坐实。

### 4.4 修复方向（推荐 1+3 组合，未实施）

1. 巡线收敛积木加"目标=当前 yaw"模式（保持当前航向语义，几秒内不漂，够用）；
2. 或脚本每站重置 IMU 零点；
3. 降低 `line_gyro_w`（陀螺只当轻阻尼；丢线期代码本就强制 w=1 咬航向）；
4. 陀螺条误差限幅（如等效 ±3° 封顶），陈旧目标不再饱和/压过相机条；
5. 比赛前提前上电预热 1~2 分钟。

## 5. 性能优化现状（帧率）

### 5.1 已做

| 轮 | 改动 | 舍弃 |
|---|---|---|
| 提帧率① | lens_corr 关闭 → **已按实车要求恢复 3.0** | — |
| 提帧率② | 剖面 13条×12px → **8条×20px**，get_statistics **106→66 次/帧** | 剖面纵向分辨率（交界行靠条间插值，损失小；20px 条反而更难采到褶皱假穿越） |
| | 落差邻域 ±2条 → ±1条 | 无（±20px 与旧 ±24px 等效） |
| | 色带 60/35 行 → 40/24 行 | 少量色彩采样面积（中位数抗污染保留） |
| | `CURVE_RMS_PX` 回 5.0 | — |
| 蜂鸣 | LED PWM 1kHz → **20kHz**（可听域外；曝光 4ms 内平均 80 个周期，相机无感） | — |

### 5.2 内置剖析器

每 `PROF_EVERY_S=2.0` 秒打印一行：

```
prof: snap=.. corr=.. 带=.. 列=.. 拟合=.. 其余=.. | 合=..ms (..fps n=..)
```

**测量必须拔掉 OpenMV IDE 只看串口**——IDE 连着时每帧压缩回传，显示帧率是假的。

### 5.3 决策树（拿到 prof 数据后）

- `snap` 大 → 降分辨率 QQVGA(160×120)，行常量全部减半（对照表已备好）；
- `列` 大 → 再砍列数/条数；
- `corr` 大 → 畸变矫正与帧率二选一（实车已定：保留矫正）；
- 帧率已 20+ 但整车响应仍慢 → 问题在 Pi 30Hz 转发节拍 + 单片机 50ms 控制周期
  （约 +66ms），改 Pi 侧"到帧即转发"（小改动）。
