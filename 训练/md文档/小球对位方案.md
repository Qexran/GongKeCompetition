# 小车-小球视觉对位方案（单帧测量 + 单次走位）

> 交接文档：交给 Claude Code 按此实现。MCU 端代码在 `GongKeCompetition` 仓库，树莓派端运行时视觉服务不在该仓库中（在 Pi 本机上，即处理串口 0xAA 协议、响应任务指令 `"5"` 的那个脚本），需同步修改。
>
> **已决策事项（不再讨论）**：
> - 不采用单应性矩阵标定（摆已知坐标点困难），使用标量比例尺 px/mm。
> - 不做迭代式"走一步看一步"（太耗时），采用**一次测量 + 一次到位**。
> - 不做连续速度环闭环。

---

## 1. 背景与问题

小车停在三个球中间位置后，用三个写死的机械臂动作组（`g_astArmAction[]` 中 ID 3/4/5 = 抓最右/中/左球，见 `Application/app_arm_action.c:145-156`）执行抓取。问题是停车位置在一个范围内波动（横向、纵向、航向都有），固定动作组经常抓空。

解决思路：停车后用主摄像头拍一次，从三个球的像素坐标一次性算出 **yaw 修正量、横移修正量、纵移修正量**，然后"原地转正 → 一次性平移"完成对位，再执行动作组。

## 2. 总体流程与时间预算

```
巡线减速接近（不变）
  → 停车（不变）
  → 发一次色球识别请求（复用现有任务指令 "5"）
  → Pi 连拍 3 帧各自处理，取中位数，回传一帧结果（含 yaw）
  → MCU 计算三个修正量：
       yaw_err   = 拟合直线角度
       横移      = (cx_中球 - 标定中心) - yaw视差补偿，换算 mm
       纵移      = (cy_中球 - 标定中心) × 纵向比例尺
  → 若 |yaw_err| > 死区：原地转正（位置模式）
  → 若横/纵移 > 死区：一次位置模式斜向平移（麦克纳姆轮可vx+vy合成）
  → 根据"目标颜色在三球中的位置"选动作组 ID 3/4/5 → 执行抓取
```

时间预算：3 帧采集 ≈ 100ms + 处理 ≈ 250ms + 转正 ≈ 0.5~1s + 平移 ≈ 0.5s，**全程 ≤ 2.5s**（迭代式要 4~6s）。

## 3. 通信协议（现状 + 扩展）

帧格式（不变）：`0xAA | TYPE | LEN | DATA[≤64] | CRC8 | 0x55`，定义在 `Application/app_rpi.h:43-54`。

现有 COORD 回传子类型 TAG=0x03（色球，`Application/app_rpi.c:785-811` 解析）：

```
DATA = [TAG=0x03][status u8][count u8] + count × [color u8][cx u16][cy u16]
当前 count=3，按 cx 升序 = 左/中/右球，LEN = 18
```

**扩展（本方案）**：在 DATA 末尾追加 3 字节：

```
DATA = [TAG=0x03][status][count=3] + 3×[color][cx][cy] + [yaw i16 单位0.01°][fit_ok u8]
LEN = 21
```

- `yaw`：Pi 端对三球质心做 `cv2.fitLine` 得到的直线角度，单位 0.01°，有符号。符号约定：**画面中三球连线左端高于右端（左球 cy 小于右球 cy）为正**（即图像坐标系 y 向下的 atan2 斜率），最终符号以标定为准，MCU 侧留配置翻转位。
- `fit_ok`：1 = 三点共线拟合残差合格；0 = 残差超限（某球识别可疑），MCU 收到 0 应重发一次请求。

MCU 解析改动：`app_rpi.c:785-811` 的 TAG=0x03 分支按 `LEN >= 21` 追加读取 yaw/fit_ok 存入结构体；`app_rpi.h` 中色球结果结构体（约 `app_rpi.h:76-83`）加 `int16_t iYaw01deg; uint8_t ucFitOk;` 字段。CRC8 表复用现有 `ucEmmV5Crc8`，无需改动。

Pi 端是老版本（LEN=18）时 MCU 忽略扩展字段、fit_ok 视为 1、yaw 用 `(cy_左 - cy_右) * K` 兜底计算——解析代码按 LEN 判断即可向后兼容。

## 4. 树莓派端视觉流水线（Pi 上的运行时脚本）

任务指令 `"5"` 的处理改为：**连拍 3 帧 → 每帧独立跑完整流水线 → 三帧中位数 → 回传一帧结果**。不做流式推送，仍是请求-应答。

单帧流水线（全部用 OpenCV 现成函数）：

```python
frame = cam.capture()                          # 原始 BGR
frame = cv2.medianBlur(frame, 3)               # 去椒盐噪声
frame = cv2.GaussianBlur(frame, (5, 5), 0)     # 抑制高频噪声
hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)

kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
for color in (RED, GREEN, BLUE):               # 三种球色
    mask = cv2.inRange(hsv, lo[color], hi[color])
    mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN,  kernel)   # 去小噪点
    mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, kernel)   # 补空洞
    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    contours = [c for c in contours if AREA_MIN < cv2.contourArea(c) < AREA_MAX]
    if not contours: 标记该色缺失
    c = max(contours, key=cv2.contourArea)     # 取最大色块
    m = cv2.moments(c)
    centroid = (m['m10'] / m['m00'], m['m01'] / m['m00'])    # 亚像素质心
```

要点：
- **用掩膜质心（moments），不用霍夫圆心**。质心对边缘缺损不敏感且更便宜。
- AREA_MIN/AREA_MAX 按分辨率（1920×1080）和球的实际大小现场调，过滤远处杂色。
- 一帧内三色全找到才算有效帧；3 帧里有效帧不足 2 帧则回传 `status=0`。

三帧融合：

```python
cx_med  = median(有效帧的 cx)     # 每颗球分别取中位数
cy_med  = median(有效帧的 cy)
pts = np.float32([[cx_med[i], cy_med[i]] for i in (左, 中, 右)])   # 按 cx 排序
vx, vy, x0, y0 = cv2.fitLine(pts, cv2.DIST_L2, 0, 0.01, 0.01)
yaw_deg = degrees(atan2(vy, vx))               # 图像 y 向下
# 共线质检：各点到拟合直线的距离最大值 < FIT_MAX_DIST_PX（建议 4px）→ fit_ok=1
```

- yaw 用**三点拟合直线斜率**而不是左右球 cy 单次差值——三点互相平均，单球抖动稀释为 1/3；拟合残差同时是免费的识别质检。
- 相机参数**锁死手动曝光/增益/白平衡**（picamera2 或 v4l2-ctl 设定），这是阈值稳定性的最大前提，比任何滤波都重要。HSV 阈值在赛场光照下标定一次。

## 5. MCU 端实现

### 5.1 新增配置常量（`Application/app_config.h`，放在现有 COLOR_* 参数附近，参考 `app_config.h:156-162`）

```c
#define BALL_CX_CENTER          960     /* 理想停止位时中间球的cx，标定 */
#define BALL_CY_CENTER          0       /* 理想停止位时中间球的cy，标定 */
#define BALL_PX_TO_MM_X         0.30f   /* 横向比例尺 mm/px，标定（现COLOR_PX_TO_MM_X） */
#define BALL_PX_TO_MM_Y         1.00f   /* 纵向比例尺 mm/px，标定（纵向像素角分辨率低，值偏大） */
#define BALL_YAW_DEADBAND_DEG   0.5f    /* yaw死区 */
#define BALL_DX_DEADBAND_MM     3.0f    /* 横移死区 */
#define BALL_DY_DEADBAND_MM     3.0f    /* 纵移死区 */
#define BALL_ROT_CX_PER_DEG     0.0f    /* 原地转1度时中间球cx的漂移量 px/°，标定 */
#define BALL_YAW_SIGN          (-1.0f)  /* yaw符号→旋转方向，标定 */
#define BALL_ALIGN_TIMEOUT_MS   1500u   /* 等识别应答超时 */
```

### 5.2 对位函数（`Application/app_rpi.c`，改造现有 `vColorApproachToTarget`/`app_rpi.c:504-530`）

```c
/* 返回：0=成功；非0=失败原因（超时/识别不全/fit_ok=0重试仍失败）
 * ucTargetColor: 要抓的球色（来自二维码结果）
 * pucPosOut: 输出目标颜色球在左(0)/中(1)/右(2)的位置，供选动作组 */
uint8_t ucRpiBallAlignOnce(uint8_t ucTargetColor, uint8_t *pucPosOut);
```

内部逻辑：

1. 发任务指令 `"5"`，等新的 TAG=0x03 应答（`BALL_ALIGN_TIMEOUT_MS` 超时）；`fit_ok==0` 或 `count!=3` 或 `status!=0` 时重发一次，再失败则返回错误。
2. 确定对位基准：**中间球**（cx 升序第二个）——车对齐到三球中点，与现有动作组设计一致。目标颜色只决定抓完对位后执行哪个动作组。
3. **yaw 修正**：`fYawErr = iYaw01deg/100.0`；`|fYawErr| > BALL_YAW_DEADBAND_DEG` 时，位置模式原地旋转 `fYawErr * BALL_YAW_SIGN` 度。位置模式运动 API 参考 `vColorApproachToTarget` 现有实现（`app_rpi.c:504-530` 里的横移是怎么下发的就怎么下发）。
4. **横移修正**（含旋转视差补偿）：转正会让中间球 cx 漂移 `fYawErr * BALL_ROT_CX_PER_DEG` 像素，需从残差中扣除：
   ```
   fDxPx  = (cx_mid - BALL_CX_CENTER) - fYawErr * BALL_ROT_CX_PER_DEG
   fDxMm  = fDxPx * BALL_PX_TO_MM_X
   ```
5. **纵移修正**：`fDyMm = (cy_mid - BALL_CY_CENTER) * BALL_PX_TO_MM_Y`。
6. 横/纵任一超死区 → **一次**位置模式斜向平移（vx、vy 同时下发，一轮运动完成）。符号现场标定。
7. `*pucPosOut` = 目标颜色球在 cx 排序中的下标（0/1/2）。

### 5.3 脚本步骤接入（`Application/app_script.c`）

新增脚本步骤 `STEP_BALL_GRAB_WAIT`（带一个参数：目标颜色，运行时从二维码结果取）。实现模式照抄 `STEP_LINE_CONVERGE_WAIT`（`app_script.c:506-517`）：

```
执行体 = ucRpiBallAlignOnce(目标颜色, &pos)
       → 按 pos 选动作组 ID：pos=0(左) → 4号? 按实际动作组命名对齐（ID 3/4/5 = 右/中/左，见 app_arm_action.c:145-156）
       → vArmPlayWait(选中ID)
失败 → 按脚本既有失败策略停车报错
```

同时需要：`app_script.h` 加步骤枚举、`Application/map.c` + `tools/webconsole/map_codec.py` + `tools/webconsole/static/app.js` 注册新步骤类型（Web 控制台能编辑它）。若地图/脚本编辑器暂时不便加动态步骤，**过渡方案**：先只加 `STEP_BALL_ALIGN_WAIT`（只对位不抓），动作组选择写死，用两个静态脚本分支跑通，再补动态选择。

### 5.4 兜底：机械臂底座偏移补偿（可选，第二阶段）

若实测底盘对位后仍有 ±5~10mm 残差：在平移完成后**加拍一帧**（只此一帧，不做循环），残差 `dx_px` 不再动车，而是调机械臂底座旋转关节：`角度 += dx_px * BALL_ARM_PX_TO_DEG`，结构照抄 `vArmAimByPixels`（`Application/app_arm.c:210-262` 的钳位 + 阻塞等待写法）。残差在几百像素内时臂关节几度即可吃掉。

## 6. 标定流程（赛前现场，约 30 分钟）

固定曝光后，在赛场光照下先标 HSV 阈值（Pi 端打印掩膜预览调试）。

1. **理想停止位中心**：用尺子把车摆在理想停止位（三球连线中点正上方、车头垂直连线），拍一帧，读中间球 cx/cy → 写入 `BALL_CX_CENTER` / `BALL_CY_CENTER`。
2. **横向比例尺**：从理想位沿横向人为挪动已知距离 d mm（贴尺子），拍一帧，`BALL_PX_TO_MM_X = d / |cx1 - cx0|`。
3. **纵向比例尺**：同理纵向挪动已知距离 → `BALL_PX_TO_MM_Y`。纵向像素角分辨率低，预期值明显大于横向。
4. **yaw 与旋转视差**：人为把车垫转已知角度（读陀螺仪），拍一帧：核对 fitLine yaw 读数与实际转角（应近似 1:1，比例偏差大则 Pi 端有 bug）；记录中间球 cx 每度漂移 → `BALL_ROT_CX_PER_DEG`；确定 `BALL_YAW_SIGN`（转正方向）。
5. 横/纵平移、旋转的方向符号各确认一次（正负号）。
6. 所有参数写 `app_config.h`；支持的话用 Web 控制台 tuning 页（`tools/webconsole/tuning.py`）在线调，免反复烧录。

## 7. 验收标准

1. 台架静态：Pi 端对同一静止场景连续 20 次识别，三球 cx/cy 中位数波动 ≤ 2px，yaw 波动 ≤ 0.2°。
2. 闭环：连续 10 次完整流程（人为扰动停车位置：横向 ±30mm、纵向 ±30mm、yaw ±3° 内），对位后中间球残差 |Δcx| ≤ 5px、|yaw| ≤ 0.5°，动作组**一次**抓取成功 ≥ 9/10。
3. 停车→机械臂启动 全程耗时 ≤ 2.5s。
4. 识别失败路径：遮住一颗球跑流程，脚本按失败策略安全停车，不瞎走位。
