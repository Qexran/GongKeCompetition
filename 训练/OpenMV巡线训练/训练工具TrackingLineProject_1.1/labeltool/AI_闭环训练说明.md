# 巡线算法 AI 闭环优化规程

> 给 AI（ZCode/任何接手的 agent）的操作说明。目标：**不上车**完成算法问题的发现、
> 定位、修复与回归验证。人在环里只做两件事：标注真值、看渲染视频确认效果。

## 一、资产地图（谁在哪里，别搞混）

```
TrackingLineProject/
├── main.py                                 ← 算法本体（工作主副本, 唯一允许改算法的文件;
│                                             与相机盘 E:\main.py 同名, 部署=直接拷贝+重启相机）
├── 校赛地图运行视频/                       ← 原始实拍视频（只读）
├── 启动标注平台.bat                        ← 双击启动平台(起服务+开浏览器)
├── harness/
│   ├── replay.py                          ← 回放器: 从 main.py exec 加载算法 → 逐帧跑
│   └── out/                               ← replay.py 的输出(CSV/分段报告/拼板)
└── labeltool/
    ├── server.py + static/index.html      ← 标注/验证平台(双击 bat 或 python server.py, :8765)
    ├── tasks/<任务名>/                    ← 切好的帧 + annotations.json(人工真值)
    │   ├── frames/0000.jpg...             ← 去重后的内容帧
    │   ├── annotations.json               ← 真值: {i:{line:[x1,y1,x2,y2]|null, state:0-4|null}}
    │   ├── report.json                    ← /compare 的输出(逐帧预测vs真值+最差帧)
    │   └── verif/ + verif.mp4             ← /render 的输出(预测烧录帧, 导出视频用)
    └── AI_闭环训练说明.md                  ← 本文件
```

**单一事实源**：算法常量与 classify_lost 等纯函数直接从 `main.py` exec 加载
（harness/replay.py::load_from_main）。**永远不要在 harness 或 server 里复制算法代码**，
改算法只改 main.py，重跑即生效。

## 二、闭环流程（每次迭代的固定动作）

1. **拿真值**：确认目标任务已有人工标注（tasks/<t>/annotations.json 里 line/state 的
   覆盖数；全部为空 → 提醒用户先标注，或仅做无真值分析）。
2. **跑比对**：
   ```
   cd labeltool && python server.py        # 平台常开也行
   POST /api/task/<t>/compare              # 或网页"比对报告"页点按钮
   ```
   读 `report.json`：summary（off MAE/最大误差、状态判对率）+ worst（off 误差 top20）
   + st_bad（状态判错帧清单）。
3. **看最差帧**：对 worst/st_bad 里的帧号, 打开 `tasks/<t>/frames/000i.jpg` 亲眼看画面,
   结合 report 里该帧的预测值/真值/-margin/点数, 写下根因假设（判据打架? 阈值不当?
   测量失效?）。
4. **改算法**：只改主文件。改前先 `cp` 一份时间戳备份到 TrackingLineProject/backups/
   （自建目录）。改动要在主文件头部变更记录里追加一行（第几次、什么根因、什么改法）。
5. **回归**：
   - 无真值体检：`python harness/replay.py`（分段报告 + 异常检测, 两个视频都要跑,
     不能比上一次差）；
   - 有真值比对：重跑 /compare, 记录指标变化（建一个 labeltool/METRICS_LOG.md 追加
     一行: 日期/改动摘要/off MAE/状态判对率, 方便看趋势）;
   - 渲染确认: /render 生成 verif 视频, 告诉用户去看（这一步是给人看的, AI 不必逐帧看）。
6. **部署**（用户操作）：把主文件拷到相机盘 main.py 并**重启相机**。相机盘上改完不
   重启不生效（踩过）。

## 三、判读 cheat-sheet（历次翻车经验, 直接查表）

| 症状 | 历史根因 | 现行机制 |
|---|---|---|
| 丢线期内标签 2/3 来回跳 | 不同证据源在退化帧轮流发言 | Δ=冻结off−直线基线(两操作数冻结→恒定); 比对 report 里 st_bad 聚集+交替即复发 |
| 全黄被报灰 | 参考色被污染/颜色票弃权后落"默认灰"兜底 | 兜底已删; 参考色只在交界行∈[70,195]的健康帧刷新 |
| 骑线帧误判 | 单个孤零星点被当证据 | 点票需 ≥2 点 |
| 深灰侧有效帧被当"正常直线" | 显示不带侧别 | [直线·黄/灰] + d=<Δ>; 比对时看 off 工作点是否系统性偏离 0 |
| 冷启动即丢线全程 st 抖动 | 基线从未建立(校赛地图2 视频即此例) | 已知边界情况; 若要支持, 需给备胎证据加去抖(未实现) |

## 四、真值口径（和标注者对齐）

- `line` = 该帧画面里**真实交界线**的位置（两点连线, 320×240 坐标）。看不见交界线的
  丢线帧不画线, 只标 state。
- `state` 语义（与算法 st 完全一致）：有效帧标 0(直线)/1(路口弧); 丢线帧标
  2(车在灰/路面侧)/3(车在黄侧)/4(说不清)。
- 真值 off/ang 由 line 用**与算法同源的公式与常量**换算（server.py::gt_from_line）,
  不存在口径差。

## 五、红线

- 不要动 `校赛地图运行视频/` 与 `tasks/*/frames/`（帧序列变了标注就全错位）。
- 不要在 harness/labeltool 里复制算法逻辑（改了不会生效, 反而骗自己）。
- 部署顺序: Pi 端解析器(4/5字段)必须先于相机端新帧格式上线（旧 Pi 解析器会拒收
  5 字段帧, 车会假死）。
- 主文件的"方向定律"注释链（第 1~7 次）是标定历史的唯一记录, 别删。
