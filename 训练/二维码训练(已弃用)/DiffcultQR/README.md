# DiffcultQR — 高难度二维码照片解码器

解码屏幕拍摄 / 强透视 / 摩尔纹干扰的二维码照片。
在本项目验证案例上（微信可扫、zxing/pyzbar/OpenCV 均失败的斜拍屏幕照片），
通过几何重建 + RS 验证暴力补全成功解出内容。

## 文件

- `decode_qr.py` — 主程序（命令行工具）
- `qrdecode.py` — V1 二维码解码核心（去掩码/之字形提取/载荷解析）
- `dev/` — 开发过程中的原型与中间产物（可删除）

## 依赖安装

### Windows / 通用
```bash
pip install opencv-python numpy reedsolo
# 可选加速快速通道:
pip install zxing-cpp pyzbar
```

### 树莓派 (Raspberry Pi OS)
```bash
sudo apt update

pip3 install opencv-python-headless numpy reedsolo zxing-cpp pyzbar
```

## 使用

### Windows 快速测试（拖拽即测）
双击运行 `test.bat`，把二维码图片**拖进窗口**按回车，即可看到解码结果和耗时：
- `[耗时] 解码管线 x.xx 秒` — 纯解码时间
- `[计时] 端到端 x.xx 秒` — 含 Python 启动的总时间

测完可继续拖入下一张，输入 `q` 退出。
（注意：`test.bat` 为中文 Windows 的 GBK 编码，请勿用 UTF-8 重新保存）

### 已知候选集加速（推荐）
如果事先知道二维码内容只在某个小集合内（如 111~333 的排列组合），
编辑 `test.bat` 头部的配置行：

```bat
set "KNOWN_DEFAULT=123"
```

写法：`123` = 三位数、每位取 1/2/3（27 种）；`12` = 每位取 1/2；
`0123:4` = 四位数；`111,222` = 显式列表；留空 = 通用模式。

命令行等价用法：
```bash
python decode_qr.py 图片 --known 123
```

原理：候选集从通用模式的约 12 万个合法短编码缩小到几十个，
逐个与采样矩阵的 ECC 校验字节精确匹配即可，解码阶段从 ~26 秒降到 0.1 秒。
候选集不含真实内容时会自动回退到通用模式（结果仍然正确，只是变慢）。

### 命令行
```bash
python decode_qr.py 图片路径 [--debug]
```

示例：
```bash
python3 decode_qr.py /home/pi/qr_photo.jpg
python3 decode_qr.py /home/pi/qr_photo.jpg --debug   # 输出 debug_warp.png / debug_matrix.npy
```

输出 `DECODED: 'xxx'` 即解码内容；退出码 0 成功，非 0 失败。

## 工作原理（四级流水线）

1. **快速通道**：zxing-cpp / pyzbar / OpenCV 直接尝试（能解就不走后续）。
2. **几何重建**：
   - 多二值化 + 嵌套轮廓(49:25:9)聚类检测三个 finder 定位图案中心；
   - 模块过小(压缩方向 <14px)时自动放大，保障亚像素边缘检测；
   - 初始单应性优先由三个 finder 的**轮廓外四边形**（12 角点）直接解出
     ——对"立起来拍"这类极端透视(单方向压缩至 50%)远比仿射可靠；
   - finder 外边缘"由外向内第一个下降沿"亚像素检测 + 直线拟合，
     结合时序图案跳变沿构成 ~170 个锚点，IRLS 稳健拟合三次多项式形变场；
   - **逐线局部残差修正**：对每条网格线在半模块带内做紧窗口(±0.35模块)
     峰值检测，中值+MAD 一致性过滤后作为逐线位置修正。
3. **模块采样**：三次场采样与逐线修正采样**双方案择优**（按结构得分）。
4. **鲁棒解码**：
   - 8 种姿态 x 4 种 ECC x 8 种掩码全枚举 + RS 纠错直接解码；
   - 失败则进入**短载荷暴力补全**：预生成 ~12 万个合法短载荷（数字/字母数字/字节
     模式）的标准编码，与采样矩阵的 ECC 校验字节做精确匹配评分——真载荷会有
     8+ 个字节精确匹配（假阳性概率 ~256^-8），不依赖采样损坏区的任何比特。

## 适用范围与限制

- 当前面向 **Version 1（21x21 模块）** 二维码；
- 暴力补全覆盖 24 位以内的载荷（约 3 位数字 / 2-3 个字母数字字符），
  更长内容需要采样矩阵错误 <= RS 纠错容量（ECC-M 为 5 个码字）；
- 屏幕照片的摩尔纹周期接近模块尺寸时仍是最难情形，本案例即属此类。

## 验证记录（本案例）

- 原始照片 1920x1080，二维码区域强透视（模块尺寸各向异性 ~40%）；
- 几何重建后模块矩阵与真实编码在可靠区域 100% 一致；
- 最终以 8 个 ECC 字节精确匹配确认内容为 `133`（与原始图 133.png 一致）。

### 速度参考（测试机）

| 场景 | 耗时 |
|---|---|
| 原图/清晰码（快速通道） | 0.06 秒 |
| 难题照片 + 通用暴力补全（12万候选） | ~33 秒 |
| 难题照片 + 已知候选集（`--known 123`，27 候选） | **~3.5 秒** |

耗时分布（通用模式）：暴力补全 ~93%，几何重建约 2-3 秒。
树莓派上整体约为此处 3~5 倍。
