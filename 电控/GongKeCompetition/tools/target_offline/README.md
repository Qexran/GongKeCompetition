# 靶心定位 —— 离线评估（打靶方案第 1 步）

合成靶 → 七套圆心算法 → 误差报告。**不碰相机、不碰固件、不碰 Pi**，纯 PC 侧。
`detect.py` 里那套算法就是将来要搬进 Pi 的 `tasks/_target.py` 的核心（纯算法、无 IO）。

```bash
cd tools/target_offline
python evaluate.py            # 全量：53 个用例 × 7 方法
python evaluate.py --quick    # 抽稀，改算法时看趋势
python evaluate.py --save     # 额外存对照图到 out/cases.png
```

判据是**命题图 7 的环半径**：10 环 Ø15（±7.5mm）、9 环 Ø30（±15mm）。
误差一律换算成**靶面上的毫米** —— 同一算法在不同距离下像素误差不同，而"能不能打中"只认毫米。

## 结论（61 个用例，实测）

| 方法 | 中位 mm | p95 mm | 最大 mm | ≤10环 | 漏检 | 耗时 | 说明 |
|---|---|---|---|---|---|---|---|
| `m_both` | 0.26 | 0.95 | 354 | **95%** | **1** | 26ms | 内边界优先、外边界兜底 |
| **`m_triple`** | 0.26 | **0.59** | 354 | 92% | 4 | 97ms | ＋跨色尺寸一致性 |
| **`m_triple_q`** | 0.26 | **0.59** | 354 | 92% | 4 | 97ms | **✅ 推荐 / Pi 侧在跑的**：`m_triple` ＋判据②' 靶环内外径比 |
| `m_inner` | 0.26 | 0.65 | 354 | 89% | 5 | 27ms | 最准，但内边界被切到就没了 |
| `m_outfit` | 0.40 | 354 | 1300 | 92% | 1 | 26ms | 只拟合外缘 |
| `m_shared` | 0.28 | 9.16 | 354 | 89% | 3 | 42ms | 同心拟合，长尾差 |
| `m_shared_sub` | 0.35 | 6.38 | 354 | 92% | 3 | 46ms | 上者 + 径向亚像素 |
| `m_hough` | 0.58 | 8.73 | 354 | 77% | 9 | 27ms | 两个参考视觉项目的做法 |
| `m_centroid` | 0.51 | 258 | **265** | 77% | 1 | 30ms | **explorer 省一队的做法** |

**推荐 `m_triple`**（跨色尺寸一致性 + 内边界优先/外缘兜底），理由见下面「判据①」。

`m_triple` 与 `m_both` 的取舍：`m_both` 漏检更少（1 vs 4）、快 3.7 倍；`m_triple` 的
**典型最坏情况更好**（p95 0.59 vs 0.95），且**唯一能解决同色圆环干扰**。
那 4 次漏检是它目前的主要短板，需要实拍数据再查。

## 三条互补的干扰判据（从现场帧推出来的）

现场背景是**一整面蓝色柜子**，蓝靶与它同色。单靠颜色阈值一定被骗，需要额外的判据。
两条判据各自管一类干扰，**互补**：

### 判据① 跨色尺寸一致性（`pick_consistent`）

三个靶并排站着，**尺寸本该差不多**；某一个突然特别大/特别小就该怀疑。

⚠️ 做法必须是「**在候选里挑一组尺寸匹配的**」，不能是「各色取最大再校验」：
现场实测蓝柜子外接圆半径 **455px**、红/绿靶 **55px** 左右，差 8.3 倍 ——
按最大取，蓝选出来就是柜子；**校验只能说明"这个不对"，给不出正确的蓝靶**
（真蓝靶在 85 个候选里排第 30 名开外）。

**它是唯一能治「同色 + 圆形 + 带孔」干扰物的判据**（蓝桶口、圆牌、圆形周转箱）：
实测「三靶+同色圆环干扰」用例，**其余 7 个方法全部偏 354mm，只有它 0.45mm**。

代价：**必须有 ≥2 个靶同时在画面里**。「单靶+同色圆环干扰」它也会失败（354mm）——
瞄准时凑近某一个靶、另外两个出画，尺寸基准就没了。而且它慢 3.7 倍（要跑三色的掩膜）。

### 判据② 内孔存在性（`fit_hole_checked`）

靶盘有「色环↔白心」的内孔，柜子、桌角、杂物大多没有。**不依赖同伴**，单靶也成立。

⚠️ 用整幅色掩膜去找孔是**错的**：画面里另一个更大的同色带孔物（蓝桶口）的内孔比靶的大，
孔的拟合会直接抓它。必须用 `connectedComponents` 拿到**只含该候选**的掩膜再找孔。真踩过。

### 判据②' 靶环内外径比（`ring_q`，2026-09 现场加）

**只筛"有没有内孔"是不够的**，判据①单独用更不够 —— 现场实测的失效长这样：

> 三个杂块（红 r=26 / 绿 r=65 / 蓝 r=50）凑巧凑成一个"尺寸大致匹配的 3 色组"，
> 于是排序键 `(-覆盖颜色数, 尺寸比)` 让**"颜色多"压过了"尺寸真的一致"**
> （那组的尺寸比是 65/26 = **2.53**，烂得很，却因为多一个颜色而胜出），
> 真靶被挤掉 → **蓝靶指向画面角落一个 r≈50 的杂块**。

补的这条判据是 **`q = 内孔拟合半径 ÷ 该候选外接圆半径`**，靶盘设计值就是
`R_INNER_OVER_OUTER` = Ø55/Ø100 = **0.55**。关键在于 **q 只看单个候选自己的形状，
跟别的候选没关系** —— 所以"几个杂块凑巧一样大"骗不过它。

现场实测（1920×1080、三靶并排、连续多帧）：

| | q |
|---|---|
| 真靶环（绿/蓝） | **0.52 ~ 0.55** |
| 蓝柜子 505px / 蓝箱 245px | 0.00 ~ 0.06 |
| 绿/红杂块 93/124/94/26px | 0.00 ~ 0.23 |
| 红靶与木椅腿的**合并块** 270px | 0.13 ~ 0.15 |

**两者完全不重叠**，所以门槛 `RING_Q_MIN/MAX = 0.35 / 0.85` 卡在中间的空白带里。

⚠️ 上界**故意放得宽**：蓝桶口那种干扰环 q≈0.75 仍能进来，它本来就该由判据①
（大 2.6 倍 > tol）拦 —— 收窄上界去抢判据①的活，会把"外环被轻微腐蚀、外接圆变小"
的真靶一起误杀。**两道关分工，别合成一道。**

⚠️ 被 q 判掉的候选**没有丢**：合并块（红靶那种 q=0.13 的）由 `find_target` 的
「目标色没被共识覆盖 → 退回该色最大候选」救回来，那个合并块的内孔正是靶的白心。
凑不齐 `min_colors` 个颜色时整条门槛**退回全部候选**，单靶场面不会被堵死。

**在本套合成用例上 `m_triple_q` 与 `m_triple` 数字完全一致** —— 这不是"没生效"：
63 个用例大多是单靶（只有 1 个颜色），凑不齐 2 色就走退回路径，门槛根本不参与。
它的价值只在**多靶同框**的真实场面上体现，所以另有
`test_ring_q.py` 用**现场那一帧的真实候选表**把正反两面都钉住：

```bash
cd tools/target_offline
python test_ring_q.py          # 9 条：旧判据选错 / 新判据选对 / 门槛不堵单靶 / 两个内孔拟合等价
```

### 判据③ ROI 裁切（`detect(..., roi=...)`）

最省事的一道：瞄准闭环本来就会把靶心拉到画面中心附近，所以「靶心应该在的地方」是个
**已知的小窗口**，窗口外的干扰**根本不用去看**，而不是"看了再去排除"。
全部参考项目用的都是固定 ROI。

⚠️ **窗口形状要按现场排布定**：三个靶**水平并排**、柜子在**上方背景** → 该用
「全宽 + 下移的横带」，而不是居中正方形（正方形会把左右两个靶一起切掉、尺寸基准就没了）。
真机上它就是 `TARGET_ROI_*` 一组标定量。

## 三个关键发现

### ① 纯色质心法在真实场地会灾难性失效

`m_centroid`（**explorer 省一队用的就是它**）在「同色大块干扰」用例上偏 **214mm** ——
它锁到背景上了。现场帧确认：**背景是一整面蓝色柜子，而蓝靶和它同色**。
这不是参数没调好，是「取最大色块」这个策略本身没有形状判据。

好在这个坑很好躲：先把色块按**圆度 + 内孔存在性**筛一遍，而不是只按面积取最大。
`m_both` 走的是「找内孔」这条路，天然免疫。

### ② 真靶的外边缘不是圆，内边界才是

现场样件是手工/3D 打印的，外缘是**手工贴的**。拿实拍帧量（2026-09）：

| 特征 | 拟合椭圆残差 std | 像素化下限 | 判定 |
|---|---|---|---|
| 外边界（色环外缘） | **2.15px**（最大 5.8px） | ~0.3px | **物理上就不是圆锥曲线** |
| 内边界（色环↔白心） | **0.44px** | ~0.3px | 干净的圆 |

所以「以哪条边为圆心依据」是个真问题。这也解释了为什么 `m_outfit` 在中位数上不如
`m_inner` 却更稳 —— 它的 MAD 裁剪能吃掉波浪，但吃不完全。

### ③ 手工样件上**没有 8/9/10 环**

命题图 7 画的是「外环着色 + 内圈 8/9/10 环」，但现场样件白心上**没印内环**
（队伍也不确定正式靶有没有，按「没有」设计）。

后果：**「共享圆心同心环拟合」这个思路可用，但只有两条圆边可用**，
不能指望"四圈一起约束"来压噪声。`m_shared` 的长尾（p95 4.56mm）就是这么来的。

## 踩过的坑（都已修，别再犯）

### `abs((better or c)["r"] - med)` —— 最值循环的经典初始化错

`better` 为 `None` 时 `better or c` 就是 `c`，比较变成 `abs(c.r-med) < abs(c.r-med)` **恒假**
→ `better` 永远设不上 → 蓝靶换不掉 → 随后被"尺寸不一致"整个剔除 → 回退到最大候选（桶口）。
症状是「尺寸判据看着没生效」，实际是循环没写对。正确写法拿当前 pick 当初始最值。
**这类 bug 只有跑用例才看得见**（`m_triple` 在圆环干扰用例上偏 354mm）。

### 合成图贴了个黑方块

`compose()` 原来拿**整块画布**当遮罩，而画布在靶盘以外是黑的 → 把靶盘连同一块黑方
一起贴进画面。那块黑方的四条直边是极强的灰度边缘，把边缘点拟合整个带偏
（`m_shared` 在遮挡用例上偏 20mm）。**症状看起来像算法问题，实际是渲染器问题。**
现在 `render_target_canvas()` 返回圆盘 alpha 做遮罩，并做软混合避免锯齿。

教训：**边缘类算法出怪结果时，先看图，别先改算法。**

### 按半径直方图裁剪边缘点是负收益

`trim_by_radius()` 假设"合法点聚成少数几个半径尖峰"，但遮挡物的直边在半径直方图上
同样会造出密集格 → 该留的被丢掉、该丢的留下来。实测在遮挡用例上把误差从 1.0mm
**拉到 3.7mm**。已把默认改成关闭，代码里留了实测数据。

要真做对得用 RANSAC/IRLS，留到有更多实拍数据再定。

| `synth.py` | 合成靶渲染。几何按**现场实拍**（不是命题图）：外圈白背板 → 色环（外缘可加波浪）→ 白色圆心盘，默认**不画内环**。相机模型是物理正确的（`H = K·[r1 r2 t]`），真值圆心是算出来的，不是标的 |
