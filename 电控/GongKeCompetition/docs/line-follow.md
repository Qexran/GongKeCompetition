## ⚠️ 支点转弯 → 巡线接管（`STEP_PIVOT_LINE_WAIT`，2026-09 加）

**巡线起流与转弯重叠**：转弯误差进 `PIVOT_LINE_HANDOFF_DEG` 就松手，`vx`/`w` 都交给巡线，省下 4 拍稳定窗（~200ms）+ 起流等待 + 一次「停稳再起步」。

**交接后听谁的航向 = 全局调参宏 `LINE_CONV_SRC`**（2026-10-30 起不再是积木参数；出厂 3=融合）；选陀螺/融合则**咬住 `gyro_target` 那个绝对世界航向**（两段巡线共用此档位）。`ucRpiLineSrcResolve()` 是两者**共用**的取值校验（越界/笔误 → 拒绝 + 不修航向; 不响, 留痕）。

```
① vRpiSendTaskCmd(LINE_START)        ── 先取帧计数基线（车还没动）
② vPidPivotTurnUntil(..., ulFrame0)  ── 边转边等起流; |err|≤阈值 且 帧已起流 → 松手
②′ fwd_ms>0 时按体坐标系直行一段再停
③ 转完还没起流 → 补等到"起流超时的截止时刻"; 仍没有 → 收尾拒绝（不重复转, 不响）
④ 巡线接管（同一个内层闭环连调两段）: settle_ms 只对准修 vx/w 不前进; line_ms 沿线走边修边走
⑤ vRpiSendTaskCmd(LINE_STOP)         ── 无条件
⑥ tail_ms>0 时尾段盲走再停
```

**⚠️ 四个时长都是积木参数**（`fwd_ms`/`settle_ms`/`line_ms`/`tail_ms`），2026-09 分两步到位：
1. `line_ms` 原只做横移+转正（`vLineFollowConverge` 里 `v_y` 恒 0）→ 加 `int iFwdRpm`：**0 = 只横移 + 转正**（`STEP_LINE_CONVERGE_WAIT` 走这条，与加参数前**逐字节等价**），**≠0 = 边前进边修**。
2. 「收尾窗」原为**宏** `PIVOT_LINE_SETTLE_MS`（积木看不见也改不了）→ 提成参数 `settle_ms`，宏**删掉了**。
3. 2026-10 加的 `tail_ms` = **尾段盲走**（线到头了还得往前顶一点）。
   ⚠️ **它排在 `LINE_STOP` 之后**（那段不看线，先停掉 Pi 的流收相机）;
   ⚠️ **它追加在 int 末尾（I(6)）**，map.c 那几行老行**不必重写**（缺的尾槽归 `0` = 不盲走）—— 与第 1、2 两次「必须全量重写」相反, 别搞混。

- **三段前进**（fwd / line / tail）**速度共用宏** `PIVOT_LINE_FWD_SPEED`，都走 `ucTurnLineBlindDrive()`、都是**体坐标系**；`settle_ms` 段只对准、不前进；**⑥ 与 ②′ 是同一种动作**。（该助手原名 `ucPvlBlindDrive`，2026-10-30 抽共享尾段时改名 —— 支点与自转两条组合动作共用。）
- **④ 两段是同一内层闭环连调两次**：前段结尾的 `vChassisMove(0,0,0)` 被后段**第一拍立刻覆盖**（微秒级），没有「停稳再起步」；`line_ms`→`tail_ms` 同理。⚠️ `settle_ms` 与 `line_ms` 都为 0 时**仍跑一拍**（兜底成 `LINE_LOOP_PERIOD_MS`）—— 交接**不停车**；**尾段不参与这条兜底**。
- ⚠️ **别把全局的 `LINE_CONVERGE_SAMPLES` 调大**：那个提前退出判据（|err|≤阈值连续 N 拍）在 `line_ms` 段就是**截断行程**（走半截就停），要保持 0（当前默认值）；它对 `settle_ms` 段有益。

**⚠️ ②′ 直行走「体坐标系」** —— `vChassisMove(0, PIVOT_LINE_FWD_SPEED, 0)`，**不是** `vChassisMoveWorld`（世界系要读航向累加器，交接那刻它刚按「实测」写过）；时长 = `fwd_ms`（`0` = 不直行），快慢 = 宏 `PIVOT_LINE_FWD_SPEED`(60rpm)。

- ⚠️ 代价：交接时航向残差最多 `PIVOT_LINE_HANDOFF_DEG`，直行会把它**变成横向偏移**（位移 × sin(残差)），由巡线环修掉；嫌多就调小 `HANDOFF_DEG`。尾段盲走同理：**纯开环**，偏差照原样带过去。
- ⚠️ 盲走段结束**必须停车**（速度模式指令是持久的，「降级跳过巡线」那条路不停车会让车**一直往前跑**）；代价 0~50ms —— 下一拍巡线环就会按 `iFwdRpm` 重发。尾段与 `line_ms` 段之间**没有刻意的停顿**：前进量 ≈ `tail_ms × PIVOT_LINE_FWD_SPEED`，但节拍是 `PIVOT_TURN_PERIOD_MS`(50ms) 的**整数倍**、**落点仍按实测补时长**。

**⚠️ 老底盘 bug（2026-09）**：`vChassisMove` 下标曾与电机地址交叉（`speed[1]`↔电机 2、`speed[2]`↔电机 1）→ 症状「**前进**时**只有电机 1 和 2 转反**」；现 `speed[n]` = 电机 n。（横移一直没暴露：`v_x>0` 时电机 1/2 的方向字节本来就一样、都是 CW，交叉了看不出；前进时两者相反，交叉立刻显形。）**判据**（改 `vChassisMove` 前必对照）：前进方向字节要与 `vChassisMoveDistanceY` 的**位置模式**表逐位相同 —— 下标=电机地址 1..4、`v_y>0` 为 `{1:0(CW), 2:1(CCW), 3:0(CW), 4:1(CCW)}`（`s_aucFwdDir`）。

**⚠️⚠️ 「重叠」是这一步唯一存在的理由，别写成串行**（串行写法「先发 `LINE_START`、等满起流、再转」总时长 = 起流等待 + 转弯，**一点没省**）：把**两个判据都塞进支点转弯的闭环**，每 50ms 顺带看一眼帧计数 —— Pi 起流那几百毫秒正好被转弯吃掉。代价：Pi 不起流时车照常转完，再**补等到截止时刻** → 总时长上界 = `max(转弯时长, LINE_FIRST_FRAME_TIMEOUT_MS)`，**不是两者相加**。

**三个刻意的取舍**（详见 `ucRpiPivotTurnLine` 函数头）：

| 取舍 | 为什么 / 代价 |
|---|---|
| 交接**不停车** | 驱动侧残留转速（≈`KP×HANDOFF_DEG`≈30rpm）交给巡线第一拍覆盖，省一次停稳再起步。代价是「滑行角」—— 冲过头先**调小 `HANDOFF_DEG`**，别加大 `LINE_CAM_TO_W`（纯 P，调大只会更抖） |
| 链路不通**直接转完** | 转弯是纯本地动作、Pi 不在也干得了。所以**不用** `ucRpiSendTaskCmdWait`（那会不封顶地等重连、反复重启 Pi 客户端，期间**车停在原地不转**）—— 这是对「发起任务用带链路入口」那条通则的**有意例外**，别顺手改回去 |
| 巡线段听谁 = **全局宏 `LINE_CONV_SRC`** | 档位同「巡线收敛」（相机/陀螺/不修/融合，出厂 3=融合）。⚠️ 2026-10-30 前是积木参数 `src`（更早写死"强制纯相机" `vSetLineGyroW(0)`）；"交接后咬一个绝对航向"用 `LINE_CONV_SRC=1/3` + `gyro_target` |

**两个新宏**（`app_config.h` 支点转弯段）：`PIVOT_LINE_HANDOFF_DEG`(10°)、`PIVOT_LINE_FWD_SPEED`(60rpm)；**时长全是积木参数**，宏只管阈值与速度。标定顺序：`HANDOFF_DEG`（看落点，冲过头调小）→ `fwd_ms` → `line_ms` → `FWD_SPEED` → `tail_ms`（**前面都定下来之后**再补，否则会和 `line_ms` 互相掩盖）。

**⚠️⚠️ 积木参数现在 2 个 float + 7 个 int（`angle / gyro_target` + `dir / absolute / fwd_ms / settle_ms / line_ms / tail_ms / settle_early`），宏是 `SCRIPT_STEP_F2I7`** —— 工程里最宽的一条（航向源/占比已提到全局 `LINE_CONV_SRC` / `LINE_CAM_PCT`）。抬宽度要**三处一起动**：`app_script.h` 补全该族 1..上限、`map_codec.MACRO_CAP_F2I`（或 F1I）、`test_server.py::TestSerializeStep` 家族表（该表直接引用 `MACRO_CAP_*` 常量逐族核对，抬常量即自动跟）。
⚠️ **控制台按「先所有 float、后所有 int」的**位置**读写参数**，故**动了任何一族的相对位置，老行就必须全量重写**：
- 加 `settle_ms`：原 `(…, 0u, 0u, 0u, 1500u)` 的 `1500` 是 `line_ms`，当 5 槽读会变成 `settle_ms=1500, line_ms=0`（编译照过、照显示）。
- 加 `gyro_target`（**新增 float 槽**）：老行**第一个 int 被当成这个新 float 读** —— `dir=1` 变成 `gyro_target=1.0f`、`absolute` 变成 `dir`… **转向整个错位**；`map.c` 那 3 行（预设 1 两处 + 预设 22）已重写成 F2I6，重写一律用 `map_codec._serialize_step` 生成（见「脚本动作表设计规则」第 8 条）。
- ✅ 反例（2026-10 加 `tail_ms`）：它**追加在 int 末尾**（I(6)）、两个 float 与六个老 int 位置一个都没动 → map.c 那几行**一个字节都不用改**（缺的尾槽补 `0` = 不盲走；前端 `paramInput` 对 `undefined` 槽回空串、服务端 `_normalize_param("")` 补 `0`）。**能往末尾追加就别插中间**。
- ✅ 同理（2026-10 加 `settle_early`）：**追加在 int 末尾**（现为 I(6)，布局 F2I7——2026-10-30 删 src/cam_pct 后）—— 老行缺槽补 `0` = settle 段跑满 = 老行为。它**只作用 settle_ms 段**：勾"是"时该段按「巡线收敛增强」判据**对准即提前进下一段**（没判到最多再给 `LINE_CONV_OVERTIME_MS` 超时收敛）——settle 与「巡线收敛」同为"只对准"语义，交接残差小时省白等；**line 段时长=行程、恒不吃**（提前退=少走），fwd/tail 盲走无判据。
⚠️ 改完 `app_script.h` 要**重启控制台 + Ctrl+F5**：浏览器里那份 catalog 还是旧槽位数，拿它保存会把新参数无声吃掉。

**⚠️ 交接要先「武装」**：进循环前先量一次初始误差，`|初值| > 阈值` 才启用交接 —— 否则「相对转 5°」而阈值 10° 时会首拍就 `|err| ≤ 阈值`、**一步不转就松手**。这道门**只看误差、不看帧计数**；且要求 `HANDOFF_DEG > PIVOT_TURN_CONVERGE_DEG`，不然收敛带先触发 → 永不交接。

**⚠️ 排障看 `PVL:` 串**（本步**必须自己发**，与 `LINE:` **内容互补**：`LINE:` 已无条件打、只会照实报 `src` 档位，而「**为什么没走巡线**」只有 `r=` 说得清、总耗时只有 `t=` 有）：`PVL: r=2 t=2130ms`，`r` = 0 链路不通跳过巡线 / 1 没起流跳过巡线 / 2 交接成功 / 3 转完再巡线 / 4 被中止；`t` = 本步总耗时（与老两块积木比这个数即知省没省）。
⚠️ 本步调两次内层闭环，一次 `PVL:` 通常配**两条** `LINE:`；尾段盲走**不产生** `LINE:` 但算在 `t=` 里 —— 反推巡线段时间时记得减掉这四个时长。

**⚠️ 前提是转弯终点能看到线**（排表的人保证）；看不到线时 Pi 会按它的定向找线策略做大横移，那不是本步要的。

**顺带修掉的一个旧洞**：支点转弯的闭环现在**查中止位了**（`ucGetScriptAbortReq`，走 `ucAbort` 收尾 = 停车 + 按实测写航向），于是 **`STEP_PIVOT_TURN_WAIT` 从此可被 OLED 菜单中止**（以前要干等满 `PIVOT_TURN_TIMEOUT_MS`）。`map.c` 里老的行一个字节都不用改。

## 原地转弯 → 巡线接管（`STEP_SPIN_LINE_WAIT`，2026-10-30 加）

支点接管的**四轮自转版**：转弯本体换 `vPidSpinTurnUntil`（`SPIN_TURN_*` 增益，四轮对称反向出力、**车心不动** —— 支点版单侧驱动、车心会平移），**交接后的全部段与支点版共用同一份代码**（`app_rpi.c::s_ucTurnLineTail` —— 2026-10-30 从支点版里抽出来，就是为了两条路不各自漂移）。积木参数与支点版**逐位同形**（F2I7：`angle/gyro_target` + `dir/absolute/fwd_ms/settle_ms/line_ms/tail_ms/settle_early`；航向源/占比是全局 `LINE_CONV_SRC` / `LINE_CAM_PCT`），`settle_early` 的语义、四个时长的排布、"settle 与 line 都为 0 仍跑一拍"的兜底、链路不通降级成完整转弯 —— **全部照上面那节**，排表经验可互相套用。

与支点版仅有的两处不同：

- **调试串前缀 `SPIN:`**（支点版 `PVL:`）—— `r`/`t` 码含义完全相同（2=交接成功 / 3=转完再巡线 / 1=没起流 / 0=链路不通 / 4=被中止）。Pi 日志里两条串一眼分清是谁在跑。
- **交接瞬间的残留自转约支点的 2 倍**（差速自转 ω=2v/轮距）：同一个交接阈值（**刻意共用** `PIVOT_LINE_HANDOFF_DEG`，没为自转单开旋钮 —— 少一个要标定的数）下，巡线第一拍要多修一些。残留冲过头先**调小 `HANDOFF_DEG`**。自转的残留是**四轮对称**的，巡线环第一拍的 `vChassisMove(fVx, fY, fW)` 覆盖全部四轮 —— "交接不停车"在自转版反而更干净（支点版只覆盖驱动侧）。

**选型**：交接后要**原地对准、车心不许漂**的场合用本积木（站位紧凑 / 排线密的区段）；转弯过程顺便平移一段没坏处的场合，支点版到位更快（单侧驱动本身就带位移）。

## 巡线直走（`STEP_LINE_STRAIGHT_WAIT`，2026-10 加）

**要解决的问题**：「支点转弯接管」的沿线段（`line_ms`）时长靠人拍脑袋、速度写死 `PIVOT_LINE_FWD_SPEED`；「巡线收敛」只对准不前进。这块新积木 = **沿线边前进边修走固定距离**：`mm` 按位置模式**同一条梯形估时公式**反推闭环时长，前进速度与加速度都是积木参数。

**参数（F2I4）**：`F(0)=dist_mm`、`F(1)=gyro_target`（全局 `LINE_CONV_SRC=1/3` 时参与）；`I(0)=accel`、`I(1)=speed`、`I(2)=use_res`（不吃残留=0）、`I(3)=settle_ms`（**起步对准段**，0=不对准）。航向源 = 全局 `LINE_CONV_SRC`，融合占比 = `LINE_CAM_PCT`（2026-10-30 起不再是积木参数）。原语 `ucRpiLineStraightWalk`（app_rpi.c），链路 = `ucRpiLineRun` 加了 `iFwdRpm`/`iAccel`/`ulSettleMs` 三个透传参数，起流/等流/收流与「巡线收敛」**同一条龙**（成败都不响, 留痕）。

- **⚠️ 起步对准段 `settle_ms`（照搬支点转弯 ④ 的 settle→line 结构，2026-10-05 加）**：起流门过后先**原地**收敛 `settle_ms`（iFwdRpm=0，用「原地对准」增益组）再沿线走 —— 把摆歪的起步先修掉。**这是「直走不纠偏」的正解**：直走没有对准段时，车从摆歪状态直接全速前进，修正追不上发散（实测 1000mm/913ms、speed=210、摆歪起步，vx 严格跟随 err 但 `e` 仍从 −0.26 恶化到 −0.53）；支点接管好看正是因为转弯+settle 已把车摆正。摆歪多的段落 settle 给 800~1500ms；`LV:` 遥测里对准段 `f=0`、沿线段 `f=210`，两段一目了然。

- **增益两组分开（2026-10-05 拆，横向 + 航向）**：边走边修的段（本积木、接管沿线段，即 `iFwdRpm≠0`）用 **`LINE_WALK_STEER_TO_VX` / `LINE_WALK_CAM_TO_W` / `LINE_WALK_GYRO_TO_W`**；原地对准的段（巡线收敛、接管 settle 段，`iFwdRpm=0`）用 `LINE_STEER_TO_VX` / `LINE_CAM_TO_W` / `LINE_GYRO_TO_W`。道理：**前进本身会让横向偏差发散**，歪头前进更要靠旋转环把车扳平——实测（1000mm/913ms、speed=210、故意摆歪）vx 严格跟随 err（WALK=50 时 −0.26→−9、−0.53→−18）但 `e` 仍从 −0.26 恶化到 −0.53：歪头（图像角 −3°≈真偏角 −10°）的发散 ≈210×sin(10°)≈36rpm 当量，vx+w 追不上；而支点接管好看是因为转弯+settle 已把车摆正、且只走 60rpm。Pi 端 `LINE_KP` 与限幅（`LINE_VX_MAX`/`LINE_W_MAX`）两组共用；直走要更猛只调 WALK 组（航向增益建议先 −4），效果看 `LV:` 的 `vx`/`h`/`w` 列。出厂各值与对准组相同（行为不变）。

- **估时**：`fChassisMoveTimeEst(dist, accel, speed, AXIS_Y)` —— 体坐标系前进，与位置模式平移同一把尺。⚠️ **速度模式斜坡与位置模式共用同一个 EMM 加速度档位**，公式才迁移得过来 —— 因此 ① `accel` 钳 **1~255**（EMM 单字节档位；0 = 直接启动而估时把它当 256，>255 截断会把"估时的加速度"与"实际斜坡的加速度"劈开）；② 拆了 **`vChassisMoveA(vx,vy,w,accel)`**（app_chassis.c，`vChassisMove` 变成取 Beam 底盘加速度的薄壳），`vLineFollowConverge` 加第 4 参把斜坡跟到每条速度指令（含停车/掉线停车 —— 估时假设对称梯形）。**老调用全传 `iGetChassisAccel()` = 行为逐字节不变**。
- ⚠️⚠️ **时间系数 k = Beam `line_time_scale`**（蓝牙「巡线」组当场改，断电回 `app_config.h` 的 `LINE_TIME_SCALE`=1.0）：实际闭环时长 = 估时 **× k**。**估时公式搬到速度模式斜坡上带系统偏差（实测偏长）**，k 就是那把现场标定的尺：**走过了调小(<1)、没走到调大(>1)**，落点偏差**全折进 k**、别去改 dist_mm（那是"要走多远"的语义）。50ms/拍的取整余量、每拍 4 帧的发送开销、EMM 斜坡的离散档位全都吃进这一个系数里。步末串里的 `k=` 就是本步实际用的值。
- ⚠️ **`use_res=1` 吃「路径残留偏移」**（人质单动作抓取留下的世界系 mm，读出即清零）：残留经 **`vChassisWorldToBodyEx`**（2026-10 公开的壳，与 `vChassisMoveWorld` 的 use_res **同一张象限表**）按指令航向折到车体，**fwd 分量并入 `dist_mm`**（计划 − 残留：车已经多走多少就少走多少，抓取时后撤过则多走）；**side 分量本积木不走、丢弃并在 `LW2:` 对账串报出** —— 横向本就该由后面的巡线收敛修，拿到这里是重复补偿。折算在估时**之前**（距离变了估时才对）；**防呆没配齐的积木不消费残留**（吃了白吃）。
- ⚠️ **实际时长取整到 `LINE_LOOP_PERIOD_MS`(20ms) 拍**（闭环逐拍重发速度指令），平均比(估时×k)多约半拍。`dist ≤ 2mm` 吃估时函数的 **200ms 地板**（毫米级小步别用这块）。
- ⚠️ **防呆**：`dist/speed/accel` 任一 ≤0（新拖出的积木=没配齐）→ 拒绝 + 一步不动（不响, 留痕）、**连巡线流都不起**。走完**按源写世界航向**：陀螺档写**指令目标**（90° 逻辑网格，不写实测 —— 实测会把航向环残差渗进账本），相机/融合写实测（线才是航向基准），不修档不写；只有真跑过才写。
- ⚠️ **`LINE_CONVERGE_SAMPLES` 必须保持 0**（全局宏）：它的提前退出在这里就是**截断行程**。前提同支点转弯：**这一段看得到线**。
- 排障：`LW: d=<实际mm> t=<时长>ms k=<系数> r=<0|1>`（r=0 参数没填/链路不通/没起流）+ `LW2: res=(wx,wy) body=(side,fwd)`（只在该次勾了 use_res 时发）+ 内层闭环的 `LINE:`，互补不重复。
- **过程遥测 `LV:`**（2026-10-05 加）：巡线闭环**运行中**按 `LINE_LIVE_TELEM_MS`（默认 250ms，0=关）节拍发 `LV: t=<s> e=<横向偏差> h=<航向误差> vx=<横移指令> w=<旋转指令> f=<前进分量> v=<是否在线>` —— 边走边修的步骤在 Pi 日志里的**过程录像**：误差怎么变、横移/旋转各打了多少、哪一拍丢的线全在这条里（丢线 v=0 的拍也发）。vx 符号 = `vChassisMove` 约定（v_x>0=右移）；巡线收敛/支点接管的各段同样会发。嫌日志吵就调大间隔或设 0；车上同屏可看 OLED 第 4 行 `Spd:vx,vy,w`（同一组指令值）。
- **步末 Yaw 记录 `LINE yaw:`**（2026-10-10 加）：本闭环**结束**（收敛跑完 / 超时 / 被中止都算）时记一条 `LINE yaw: <Yaw>` —— 「调参」Tab 的 `LINE_END_YAW_DBG`（**默认 1=开**，`@(0~1)` + 备注写 `0=… 1=…`，不是 `{...}`）开关，走 `#if` 编译期剔除（关掉时连字符串一起消失）。它挂在 `vLineFollowConverge` 末尾，所以「巡线收敛」/「支点接管的沿线段」/「巡线直走」/「单动作抓取里那次并行收敛」**都会发**；读的是 `fGetAttitudeYaw()` = **工作航向**（与 OLED 第 1 行、各航向闭环同一个数，`ROADYAW_APPLY_EN=1` 时已扣看路校准偏置）—— 一条路线跑下来把这些数排在一起就能看出陀螺漂移趋势与"这一段把车头转歪了多少"。⚠️ 它**不并进 `LINE:`**（那条已接近 `RPI_DATA_MAX`(64) 的静默截断线），两者互补。

## 巡线收敛增强：「启动即返回」+ 超时收敛（2026-10 加）

**要解决的问题**：「巡线收敛」按固定时长跑，一开始就对齐的地方白等满（该提早走）、偏得厉害的地方没调完就被掐（该多给时间）。

**两个新旋钮**：
- **积木参数 `early_ret`（启动即返回{1=是,0=否}）**：位于 **I(1)**（2026-10-30 删 src/cam_pct 后本积木是 F1I2）——map.c 老行缺的尾槽补 0 = 否 = **老行为**。勾"是" = 逐拍查「收敛完成」判据，达标即提前返回（实际耗时 0 < t < 收敛时长）；收敛时长内没判到 → 再给「超时收敛时间」，期间判到随时走，到点才强制结束。勾"否"时超时收敛时间**完全不参与**。
- **调参 Tab「超时收敛时间」`LINE_CONV_OVERTIME_MS`**（默认 1500）：上面的超时收敛上限，0=不允许超时。

**「什么时候算收敛完成」= 调参 Tab 新参数区「巡线收敛增强」**（`app_config.h`，`LINE_CE_*`）：位置误差 `LINE_CE_POS_TH`（**总闸**，=0 整套增强失效，勾"是"也退回跑满）**且** 航向误差达标（按全局 `LINE_CONV_SRC` 选中的源判：相机看 `LINE_CE_ANG_TH_CAM` / 陀螺看 `LINE_CE_ANG_TH_GYRO` / 融合两源各判各的 / 不修就只判位置；阈值 0=不判该源），**连续**满足 `LINE_CE_STABLE_MS`（默认 100ms≈3 帧）才算数。

- ⚠️⚠️ **航向阈值必须 ≥ 对应源自己的死区**（`LINE_CAM_DEADBAND_DEG`/`LINE_GYRO_DEADBAND_DEG`）：控制器在死区内不出力，误差压不进比死区更小的阈值 → **永远判不到收敛 → 每次都白吃满超时**（默认 1.5/3.0 已按死区 1.0/2.0 留了余量）。
- ⚠️ **判据只在 `valid=1` 的帧上累加**，丢线/IMU 停摆/Pi 停发那一拍 = 不满足并清零稳定窗；Pi 起流盲期发的就是 `valid=0` 的帧（`tasks/_line.py`），**不会被上一次运行的陈旧快照骗成"已收敛"**。
- ⚠️ **与老判据互斥**：增强启用时全局宏 `LINE_CONVERGE_SAMPLES` 那套不参与（反之亦然）；`SAMPLES` 仍必须保持 0（直走/沿线段的理由没变）。
- ⚠️ **谁吃这套判据**：「巡线收敛」积木勾 `early_ret=是` 全程判；**支点转弯接管只有 settle 段**（积木 I(6) `settle_early=是` 时——settle 与它同为"只对准"语义，交接残差小就提前进下一段，没判到最多再给超时收敛时间）；**line_ms 段 / 巡线直走 / 单动作抓取里的并行收敛恒不参与**——它们的时长=行程或与臂并行的窗口，提前退出=截断。想让别处也用，先想清楚截断语义。
- **排障**：勾"是"的积木步末多发一条 **`LINE conv: t=<实际> lim=<上限> r=<0|1|2>`**（与 `LINE:` 互补）：r=1 收敛时长内提前收敛 / 2 超时段才收敛 / 0 跑满仍未收敛。**常态化 r=0** → 先查航向阈值是不是 < 死区，再谈车是不是真没对齐（`LINE:` 里的 `a=`/`err=` 就是当时的读数）。
- ⚠️ 改了 `app_script.h` 的槽位：**控制台要重启 + Ctrl+F5**（旧 catalog 会把新参数无声吃掉）；`test_server.py` 的槽位契约测试（`test_line_converge_param_layout` / `test_early_ret_slot_is_a_yes_no_dropdown`）钉死了 early_ret 在 I(1)。
