# 单动作抓取（色球 / 人质）

> 由根 `CLAUDE.md` 拆分；章节标题保持原样（源码注释按节名引用）。
> 相关：`docs/vision-tasks.md`（色球与人质识别链）、`docs/target.md`（路径残留偏移）

## 单动作抓取（`STEP_BALL_GRAB_ONE_WAIT` / `STEP_HOSTAGE_GRAB_ONE_WAIT`，2026-10 加）

**与排爆/反恐两块并存的新方案**：老方案左/中/右各录一个抓取动作，落点容忍度全压在三个录制位姿上（实测 ~八成成功）。新方案**只录一个"抓中间目标"的动作** —— 到区后照老逻辑识别拿到目标位置（0左/1中/2右）与**中间目标**偏差 dx/dy，平移 = dx/dy **叠加 (位置−1)×`one_lat_mm`**，把目标挪到"中间正前方"再抓那个唯一的动作。识别链路、二维码键、标定量全部复用现成的（球=BALL_*、人质=hs_*），**Pi 端一个字不用改**。

**色球版（`ucRpiBallGrabOne`，参数：超时/mode/抓取动作/放置动作/提前量/放置延时/反向/单步确定）**：识别定位 → [mode 纠正] → 平移 → 抓取（`vArmPlayNoWait` 入队即返）→ [mode=2 并行巡线收敛] → 等臂空 → **只回退间距分量** → 放置入队 → [mode=2 再并行收敛] → 等臂空。结束时车停在对齐位、清残留偏移。⚠️ **回退量是间距分量、不是整段平移**（2026-10-03 台架实测定的：旧版整段回退把"对齐 dx/dy"也撤了，抓中球放置时车溜回块前的偏移位——用户原话"它应该不动，因为它已经在中间对齐好的位置了"）。现在侧球从"对齐位+间距"回到**中间对齐位**（=爆破桶所在位），中间球分量=0 一步不动。⚠️ 回退**串行**在臂抓完之后（爪里已有球、臂还在球排附近，并行平移会蹭相邻球）——"机械臂回来的过程中回中"落地为"抓完立即回、放置前到位"。**⚠️ 放置动作可选「无」（2026-11 加，DSL `place=放置动作<可空>`，值 0）**：**仍只回退间距分量**到中间对齐位（车停位与残留清零跟原行为一致，路线几何不用重排），只是**不投放置动作**——决赛若改成"色球只抓不放"直接选无；单步确定的最后一段也随之消失。
**⚠️ 识别失败拉回（2026-10-26 加）**：主任务路线本步常是唯一识别入口（预设 14/43 单步、无前置对位链），识别失败且 Pi 失败帧带方向（剩两球/缺端球出画面）→ 内嵌开环拉回一步（`ucBallPullbackOnce`，与 `ALIGN_PULLBACK` 同款：±`ball_pullback_mm` × `ball_fwd_sign`）再重扫一次，仍失败才 `BALL1 fail: scan` 放弃——不接则车偏出画面时一步死（"宁可赌也不空跑"）。无方向（剩球<2/Pi 旧版/链路超时）不盲走。Pi 侧的无色轮廓补救/缺球推断对**所有**发 "5" 的路径自动生效（识别函数内部，固件无感）。拉回/重扫本身不响；识别失败/超时由 `ucRpiWaitColorResult` 投失败音（每次失败一声, 2026-10-27 加）。

**⚠️ 识别段临时压灭 OpenMV 补光（2026-10-30 加，场地换边用）**：换边后 OpenMV 的 LED 热点进了主摄视野、冲淡色球识别的 HSV 阈值，而本步的 mode=2 收敛又要用 OpenMV —— 折中 = **识别窗口临时灭灯**：整个识别定位段（扫描/拉回重扫/转正复测/定位，抽成 `ucBallGrabOneLocate` 壳）包在 `vRpiOpenmvLed(0)`（发 "L,0"，临时灭、不写 Pi 配置）与 `vRpiOpenmvLedRestore()`（发裸 "L"，Pi 按它配置里记的亮度点回）之间，与看路那对（`ROAD_LED_OFF_*`）同一模式；**恢复走唯一出口，识别失败/中止也照恢复**，且任何一次巡线起流 Pi 也会自动点回（双保险）。开关/延时 = `BALL_LED_OFF_EN`/`BALL_LED_OFF_DELAY_MS`（编译期，调参 Tab；EN=0 = 老行为一字不变）。识别期间 OpenMV 流是**停的**（mode=2 的收敛在识别前已收流），灭灯对它无感；`BALL_LED_OFF_DELAY_MS`（默认 400，同看路实测起点）给主摄自动曝光留出适应"灯灭了"的时间——HSV 是阈值法，AE 追稳前那几帧颜色会漂，而标定是开灯时做的；延时只在识别段进门等一次，段内重扫不重复等。刻意不用有状态的 "T" 翻转（灯若已灭它反而点亮）。

**人质版（`ucRpiHostageGrabOne`，参数：超时/mode/抓取动作/keep_res/抓取提前量/反向/单步确定/放置动作/放置延时）**：[mode=1/2 识别前巡线收敛] → 识别定位（QR 第三位，含 `%10` 后判 1~3）→ 中间那只偏差+平移分量（平移与抓取**剩提前量异步并行**）→ [mode=2 等臂期间并行巡线收敛（2026-10-06 加，与色球同口径：底盘已空闲、臂还在播，修开环平移的横向残差）] → 等臂空 → 然后按 `place` 分两条路：
- **`place=无`（0，老行为）**：`keep_res=1` 时把实际平移量按当前指令航向折世界系记进「路径残留偏移」，**不回中不复位**，结束。
- **`place=动作`（2026-11 加）**：**只回退间距分量**回到中间对齐位（=爆破桶所在位），从回退起点延时 `place_delay_ms` 投放置动作（0=回退同时放），播完立即返回；净位移=对位修正，结束时**清残留**（此时 `keep_res` 不记账，打 `HSTG1 warn: keep_res ignored (place set)`）。现场若决赛把人质改放爆爆桶、色球改成只抓，就用这一档（色球那边把 place 选「无」）。
- 槽位 = 在 int 末尾追加：`place`(I7) / `place_delay_ms`(I8)，老行缺槽补 0 = 不放置 = 老行为；本积木因此顶到 **F1I9**（1 float + 9 int，`SCRIPT_MAX_INT_PARAMS` 天花板）。

**残留偏移机制（"叠加上次残留偏移"档）**：`path_res_x/y`（Beam，蓝牙「单动作抓取」组只读可看）存世界系残留；世界系平移积木（`STEP_CHASSIS_MOVE_WORLD_WAIT/_X/_Y`）的 `use_res` 勾 1 时本次按 **计划位移 − 残留** 执行 —— 车已偏过去多少就少走多少、抓取时后撤过就"多走"，落回路线原定终点；**读出即清零（一次性，消费走）**。换算两端共用 `vChassisWorldToBody` / `vChassisBodyToWorld`（app_chassis.c，同一张象限表互为逆）。

**反向执行（`rev` int 尾槽，2026-10-30 加，场地换边用）**：道具（球排/人质排）从路的一边换到另一边、相机/臂朝另一边看 —— 图像相对车体的两个轴向映射与"图像左=排的哪一头"**整体镜像**。积木上勾上 `rev`（下拉/勾选框「反向执行」），本步方向**整体取反**：对位 dx/dy 的方向符号（`BALL_SIDE_SIGN`/`ball_fwd_sign`、`hs_side_sign`/`hs_fwd_sign` 的**本步有效值**，蓝牙标定值一字不动）、间距分量 `one_lat_mm` 的符号、识别失败拉回的方向；色球还有 mode=1 的视觉 yaw 转正量。⚠️ **只翻方向不翻轴**（`one_lat_dir` 的 1/2 vs 3/4 选轴不受影响）；⚠️ 像素空间的标定（cx/cy 中心、px↔mm 比例尺）随镜像变了 —— 用「标定」Tab 换整套预设，与本开关无关；⚠️ 老对位链（`STEP_BALL_ALIGN_WAIT`/`STEP_HOSTAGE_ALIGN_WAIT`/矩形板心）没有这个概念，方向仍由全局标定管。**残留不受影响、这正是验收判据**：keep_res 记的是实际位移折世界系，反向后实际位移镜像、记出的残留跟着镜像，消费端（世界系平移勾"叠加上次残留偏移"= 计划−残留）公式一字不改 —— 同一个"抓左"，反向前离开时要多走、反向后自动变成少走。槽位 = int 末尾追加：色球现为 **F1I8**（rev 之后还有 2026-11 的 single_step），人质为 **F1I9**（rev/single_step 之后还有 2026-11 的 place/place_delay）；缺槽补 0 = 正向/老行为。

**单步确定（`single_step` int 尾槽，2026-11 加）**：积木上勾「单步确定」后本步**分阶段停车等 MAIN**，用来在台架/现场逐段确认动作对不对：
- 色球：`色球对位 → [MAIN] → 移动 → [MAIN] → 抓取 → [MAIN] → 放到爆爆桶`（4 段、3 次等待；最后一段仅 `place≠无` 时存在，`place=无` 则抓取即结束）。
- 人质：`人质对位 → [MAIN] → 移动 → [MAIN] → 抓取`（3 段、2 次等待；`place=无` 时抓取是最后一段，不再等）；`place≠无` 时再加 `→ [MAIN] → 放到爆爆桶`（4 段、3 次等待）。
- 每个阶段边界先 `vChassisMove(0,0,0)` 清速再等键（`ucScriptWaitKeyConfirm`，同时认中止位）；移动段用 `ucOneGrabMoveAxis` **只平移、不发臂**，抓取段在按 MAIN 后由 `ucOneGrabArmIssueNow` 立即发。
- ⚠️ 勾选后 `grab_lead_ms` **不再起作用**（移动已停稳，抓取不再与移动并行）；放置的 `place_delay_ms` 仍从回退起点计时。
- ⚠️ mode=2 的「抓取时并行收敛」在单步模式下归到**移动段末尾**（车已停、臂还没动），人质版的 keep_res 残留记账也在移动段末尾完成（**仅 `place=无` 时**；`place≠无` 时结束时清残留）。
- 老路线缺槽补 0 = 老行为（移动×提前量抓取并行），一个字节不用改。
- ⚠️ **等键时 OLED 必须停在第 1 页（状态页）**：菜单页的 MAIN 归菜单（`vSetOledMenuBusy` 掐掉了脚本那一路），与 `STEP_DEAD`/`STEP_STOP` 同一条纪律；在别的页按 MAIN 不会放行本步。

- **异步臂：抓取用「剩提前量」，放置用「起点后延时」（2026-10-23 定案）**：
  抓取 `grab_lead_ms` = 动作伸爪前段时长（动作属性，与距离无关）：`fChassisMoveTimeEst` 倒计时掉到 `lead`（再垫 `ONE_GRAB_LEAD_PAD_MS=150`，补偿估时偏紧、把触发往晚推——爪晚到无害、早到撞球）才投臂，短行程首拍即发、长行程自动推迟，0=到位后才发；两轴平移的倒计时=本轴剩余+下一轴估时（锚定**最终到位**）。**本步不等臂开始、只等它结束**。
  放置 2026-10-23 从「剩提前量」改回旧语义 `place_delay_ms`：从**回退起点**起算，延时到才投放动作（0=回退同时放）。原因=回退到爆破桶通常比放置动作短得多，剩提前量首拍即中、等于没有提前量；而且放置后不再做内部巡线收敛——放置动作播完立即返回，需要收敛的路线自己在块后排「巡线收敛」。
  `ONE_GRAB_MIN_DELAY_MS`（默认 0，调参 Tab）= **抓取**发臂最短延迟（短行程兜底；放置不吃它）。
  主路线色球 `grab_lead=800`、`place_delay=0`，人质 `grab_lead=500`（起始值，台架标定后改）。
  实现：`vChassisMoveCamera*Start` + `fChassisMoveTimeEst` + 抓取 `ucOneGrabAxisWithArm`（剩提前量）/ 放置 `ucOneGrabAxisWithArmDelay`（起点后延时），都按 10ms 切片、带中止与最短延迟处理。
  ⚠️ 双轴平移仍先 X 后 Y 串行启动（同时发两轴位置指令会互相覆盖）。
- **标定（蓝牙「单动作抓取」组，断电回 `app_config.h` 的 `ONE_GRAB_*`）**：① `one_lat_mm`＝相邻目标中心距（现场实测，默认 150 只是图纸值）→ ② `one_lat_dir`＝分量加在哪轴/哪边为正（0 不叠加 / 1,2 横向正负 / 3,4 纵向正负；平移方向反了就在 1⇄2 或 3⇄4 之间换，不用重编译）→ ③ `one_line_ms`＝mode=OpenMV 那档收敛时长。**⚠️ 本车相机装 90°（`BALL_XY_SWAP=1`），球排/人质排沿车体纵向 —— `one_lat_dir` 预期落在 3/4（纵向）那一对，现场确认。**
- ⚠️ **keep_res 与"收敛"的关系取决于间距加在哪根轴**（人质 mode=2 的收敛与块后手排的收敛同论）：收敛修的是**横向+航向**——间距加在横向（`one_lat_dir=1/2`）时横向残留会被视觉吸收，再吃残留=重复补偿，那种编法 keep_res 设 0（固件在此组合下打 `HSTG1 warn: lateral res absorbed by converge` 警告串）；间距加在纵向（3/4，本车预期档）时收敛**不修纵向**，残留照记照吃，两者可共存。新路线 26 选了残留机制（删掉了老的那块收敛，把"一步走到世界尽头"改成 `WORLD_WAIT(0, −1620, use_res=1)`）。
- ⚠️ **mode 档**：0=不纠正（依赖路线前一步已收敛）；1=视觉 yaw 转正（**色球独有**，**需蓝牙 `ball_yaw_en=1` 且 `ball_yaw_target` 已标**，没开则退化成 mode 0 并打 `BALL1 yaw: skip` 日志；人质帧无连线角没有这档）；2=OpenMV 巡线收敛（识别前一次 + 抓取等臂期间并行一次，色球还有放置时一次，**前提是该区看得到线**）。
- **⚠️ 收敛航向来源 `src`（2026-10-07 加，用户要求可选相机/陀螺——之前写死相机）**：两个积木各一个 float 槽 `gyro_target` + int 尾槽 `src`（三档同「巡线收敛」：0=相机/1=陀螺咬死 gyro_target 这个绝对世界航向/2=不修；越界由内层 `ucRpiLineSrcResolve` 拒绝兜底），积木内**所有**收敛调用（识别前/并行/放置）统一用它。⚠️⚠️ **float 槽插在 int 之前 = 老行全量重写**（宏升 F1I7/F1I6、`map_codec.MACRO_CAP_F1I` 5→7，map.c 5 行已重写）——**手改行时 float 在第一个实参位**，老值从第 2 个开始（2026-10-07 用户手改 F1I7 时把 timeout 填进了 gyro 槽 → 全部槽位错位一位：timeout=2ms、mode=29 越界、grab/place 互换，编译照过但运行全错，别再犯）。**控制台要重启 + Ctrl+F5**。
- ⚠️ **臂时序**：抓取/放置都走 `vArmPlayNoWait` + 等 `arm_seq_busy` **出现过 1 再回 0**（`ucOneGrabWaitArm`，超时 `ONE_GRAB_ARM_WAIT_MS` 继续走（不响, 留痕））。必须"见过 1 再等 0"：入队后泵最多 20ms 才认领，直接等 0 会在空窗误判完成。两步都已登记进 `c_bIsArmStep`。
- ⚠️ **`use_res` 是追加在 int 末尾的槽**（老行 `SCRIPT_STEP_F1/F2` 一个字节不用改，控制台把缺的尾槽补 0=不叠加）；单动作抓取的动作参数用 `(emArmActionIdTdf)I(2)/I(3)` 强转，控制台现在按 **float 槽数换算**（`I(n)` → `params_meta[n_f+n]`），带 float 槽的积木也能正确派生动作下拉（2026-10-23 修；此前 `I(n)` 直接当扁平下标，`grab/place` 整体错一位，`place` 退化成数字填空）。
- 调试串前缀 **`BALL1` / `HSTG1`**（老链是 BALL/HSTG）：`tgt:`（目标位置）/ `fix:`（合成平移量+分量）/ `back:`（回中量）/ `res:`（折算后的世界系残留）/ `arm wait timeout` / `abort`。排障先看 `HSTG1 res` 与蓝牙 `path_res_x/y` 对不对得上，再吃残留的那步看落点。
- **台架沙盒**：新路线（预设 26）就是实装示例（球区/人质区两处都换成了新积木，老行以注释保留）；单测人质链可把预设 26 里球区那块禁用、只跑到人质区。
