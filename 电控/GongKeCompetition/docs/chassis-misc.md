# 底盘杂项（雪弗板过坎 / EMM 环模式）

> 由根 `CLAUDE.md` 拆分；章节标题保持原样（源码注释按节名引用）。
> 相关：`docs/line-follow.md`（过坎后的视觉重同步）

## ⚠️ 雪弗板减速带过坎（`STEP_CROSS_RAMP_WAIT` → `vChassisCrossRampWait`）

**问题**：麦轮辊子对横向力零阻抗 —— 车斜着顶 10mm 台阶时只有一个前轮先接触，其接触反力的横向分量不转正车、只让整车横移；四轮受力不对称又带出偏航。

**解法**：先用很低的速度顶住坎面，靠接触反力把车**被动转正**（速度低到上不去），再用位置模式大力冲过。`app_config.h` 的 `RAMP_*` 一组是标定量（走「调参」Tab）。

**为什么「顶住」用位置模式而不是速度模式**：发一条**推进量大于停车间隙**的相对位移，被坎顶住时剩余脉冲永远完不成 = 电机一直顶住 —— 不必在循环里反复重发速度指令（每拍 4 条 EMM 帧 + 4 次 1ms 延时、还要动 Beam 底盘加速度并恢复；⚠️ 原文「各含 ~1.1ms 忙等」在 2026-09 改 DMA 后已不成立，但**结论照旧**）。代价：位置模式不写 `vSetChassisSpdCmd`，**OLED 第 4 行看不到过坎过程的速度**，标定时改看 OLED 姿态角页。

**全程不碰陀螺仪**：不用它判断「什么时候该冲」（接触后头几百毫秒内发生，顶住时长给足即可），也不用它修正航向。别再往这里加 yaw 判据 —— `vSensorTask` 是阻塞等模块上报、**没有固定周期**，任何「连续 N 拍」判据都会被帧抖动污染。

⚠️ **代价（有意选的）**：顶住期间的被动转正**真实改变了车头朝向**，而 `fGetWorldHeading()` 是航位推算量（只由 `ucPidMove` / 支点转弯 / 弧线写），本步不改它 → 那次转正的几度会作为航向误差留在累加器里，影响后续世界系平移。要治就在路线层排带 IMU 闭环的步骤，**别在本步「顺手补上」**。

**路线级约束（map.c 不动源码，排表须遵守）**：

1. **前一步必须把车停在坎前 10~20mm 且车头朝坎**。停太远，顶住时长全花在走间隙上。动作方向取**世界系前进**经 `vChassisWorldToBody` 映射到车体轴，所以车头必须朝世界前进方向。
2. **`dist_mm` 给足余量**：间隙 + 坎宽 + ≥80mm，保证任何情况下车**完全离开坎面**再往后走。
3. **动作后必须显式排 `STEP_DELAY`**（沉淀延时按设计规则第 3 条）。
4. **动作后必须接视觉重同步**（一块 `STEP_LINE_CONVERGE_WAIT`，并把全局 `LINE_CONV_SRC` 设为 **2=不修** —— 板子压在交界上相机 `angle` 不可信，故**只修位置、不修航向**；2026-10-30 起 src 不再是积木参数，只能改宏重编译）。⚠️ 2026-09 之前这是独立积木 `STEP_LINE_CONVERGE_POS_WAIT`，已并进主积木。**这一步不是可选项**：位置模式距离是**开环脉冲**，轮子打滑时位置目标照样跑完而车根本没走到，且应用层没有任何 EMM 应答解析（`app_motor.c` 把 `vCallbackFcn` 传成 NULL）→ **冲坡失败是静默的**，只能靠后面的视觉收敛兜。
5. **别在动作后接 `STEP_CHASSIS_MOVE_NO_WAIT(0,0,0)` 之类的速度停车**：那会主动中止还在进行的位置移动，车骑在坎上，紧接着的横移就正对着坎横移。

**零代码标定（正式跑之前先做）**：用现有积木在控制台「地图」Tab 拼 `SET_ACCEL(小) → MOVE_NO_WAIT(0, 小速度, 0) → DELAY(800) → CHASSIS_STOP → SET_ACCEL(还原)`，先回答：车斜着顶上去**是否真会被动转正**（不转正 → 本方案作废）、转正耗时、**在哪个速度下会自己爬上去**（取它再下调 30% 作 `RAMP_ALIGN_SPEED`）。⚠️ `SET_ACCEL` 无恢复语义，最后一行还原不能省。⚠️ 「低速」≠「低力」：EMM 是闭环步进，为维持转速照样顶满扭矩、驱动库无电流/扭矩接口 —— 只能调速度。

**顺带的组合拳**：过坎前一步排 `STEP_PID_MOVE_AND_TURN_WAIT`（带 IMU 航向闭环的平移）让车到坎时已基本垂直，本步只需处理「坎本身不垂直」的那几度。根因（接近段纯开环、yaw 误差累积）在那里治。

## 步进电机环模式切换（`STEP_EMM_CTRL_MODE` → `vChassisSetLoopModeAll`，2026-10 加）

一块积木把**底盘四电机（地址 1~4）**的开环/闭环控制模式切过来（EMM 指令 `0x46 0x69`）：

```c
SCRIPT_STEP_I1 (STEP_EMM_CTRL_MODE, "切换步进电机环模式", 2u),   // vChassisSetLoopModeAll()
```

- **参数 `mode` 的下拉只有两个**：`1=开环` / `2=闭环`（`app_script.h` 的 DSL 显式写 `{1=开环,2=闭环}`）。驱动枚举 `emEmmV5CtrlModeTdf` 另有 `0=关闭脉冲输入引脚` / `3=En 端口复用为多圈限位开关` —— 那两条**会改引脚功能**，排路线的人误点一下就是静默改掉整台车的输入行为，所以**刻意不放进下拉**。（`app_script.c` 的 case 里仍写 `(emEmmV5CtrlModeTdf)I(0)`：那是控制台认枚举类型的来源。）
- 开环 = 当普通步进用（**丢步不报错**）；闭环 = 编码器参与（有堵转/到位判断）。
- ⚠️⚠️ **存储标志恒为 0（不写驱动器 Flash）→ 掉电自动回原模式，这是有意的**（需求原话「不存储在 Flash 中，掉电即恢复」）。理由不只是省一次写 Flash：写进去改的是**整台车的持久默认行为**，而路线里没有任何一步能保证一定被跑到（急停 / 换预设 / 分支走另一支都会跳过"改回来"那一步），写坏了只能拿上位机去救。**要固化就用上位机改并存储** —— 别往这块积木加 `save` 参数。
- **瞬时积木**（发帧即完，内含每电机 1ms 命令间隔），按设计规则第 4 条**不带后缀**，建议排在**停车时**（只发这 4 条模式帧，不碰速度/位置指令）。
- 不碰舵机 → **不进 `c_bIsArmStep`**；不碰帧协议 → 树莓派那边一个字都不用改。
- 与 `STEP_EMM_ENABLE` 同构（都是「底盘 1~4 统一发一条 EMM 帧」），实现并排放在 `app_chassis.c::vChassisEnableAll()` 旁边；EMM 帧走 `vEmmV5SendCmd` 的 mutex（铁律 3），本步照旧只在任务上下文调。
- ⚠️ **老的 `map.c` 一个字节都不用改**：枚举成员虽然后移了后续成员的编号，但 map.c 存的是**积木名**（`SCRIPT_STEP_I1(STEP_EMM_CTRL_MODE, ...)`）不是数字。改完 `app_script.h` 要**重启控制台 + Ctrl+F5** 才会在积木库里看到它（浏览器那份 catalog 是加载时拉的）。
