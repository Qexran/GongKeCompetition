## 看路（`STEP_ROAD_ALIGN_WAIT` → `ucRpiRoadAlign`，2026-09 加；**2026-09-30 加横向那一路**）

**要解决的问题**：车过弯/到点全靠开环里程，现场表现是**走过头**；而车**横向**偏多少以前没人管。

**做法（第二版：整块黄色区，两个轴各一把尺）**：主摄找地面上的**黄色区**（比赛黄胶带 / 练习地图米黄篷布），它**固定在画面右上角**，车越往前开它越大、**左边缘越往左跑**：「黄色区
左边缘的 x」是一把**纵向**测距尺；同一色块的**下边缘 y** 就是**横向**那把尺（相机相对车体转了
90° ⇒ 图像 y 那条轴正是车体横向）：

```
① Pi: R−B 阈值抠出黄色区 → 取最大连通块 → 最左那一列 = **Δx**（全分辨率 px）
                                       → 该块 bbox 的**下边** = **Δy**（全分辨率 px）
       ── 0x08 帧回传（12B：Δx[0.1px] + 左边缘 ex/ey + flags + spread + **Δy[0.1px]**）
② MCU: 位移mm = (理想 − 实测) × 比例系数 × 方向(±1)
       · 纵向：Δx + `ROAD_DX_*` → `vChassisMoveCameraForward`（**一直如此**）
       · 横向：Δy + `ROAD_DY_*` → `vChassisMoveCameraLateral`（**积木参数 `use_y=1` 才做**）
```

- **判据是 R−B（色度差），不是 HSV 的 H/S/V**。实测本机位：**米黄区 +7 / 灰地 −11 / 黑线 −18 / 车身 −32**（18 级余量，**车身自被排除**）。
- ⚠️⚠️ **`ROAD_WARM_THRESH` 必须落在目标 R−B 分布的"下沿外边"，绝不能卡在分布中段** ——
  2026-09-30 实测的**头号失效模式**：卡中间 → 部分斑块过阈 → **掩膜碎成小岛** → "最大连通块"
  **逐帧换人**（870 / 1690）→ 双峰/散布判失败。同一机位：**thresh=12 → 0/3；8 → 4/4**，极差仅
  2~4px、`剔0`。⚠️ **加大闭运算核救不了**（`ROAD_WARM_CLOSE_K` 15/31/41 → 0/3、2/3、2/3，一次
  还报 1515 **错值**）。⚠️ **饱和度也分不开**：黄区 S≈28~31 vs 白板 S≈18~21（白墙也 18~21）。
  各场景 R−B：**真实比赛图（场地光）** 黄区 **+21~23**（`G−B` +20~22、`R−G≈1` = 纯黄）/ 灰地
  **0~+1** / **白色斑马线 +2~+4**（场地光下白的东西偏**冷**）→ **填 8 最稳**（黄区高 13~15 级、
  干扰低 4~7 级；填 12 余量只剩一半）。⚠️ **填 0 会误检**（灰地噪声过 0 → 掩膜贴画面左 → `Δx=0` 被 `ROAD_DX_MIN_PX` 拦掉）；填 21 吃掉黄区本体。**台架间（暖光）** 白板/雪弗板 **10~17**
  → 12 不稳、8 才稳（量的是**白板**，只是**暖光把白染暖了**）。**练习地图** 米黄篷布 +7 / 灰地
  −11 → 要**更低**。**到场先**开预览看：① 黄区被框住 ② 白的东西/车身不在框里 ③ **掩膜
  不是"碎岛"**（碎 = 阈值卡在分布里，往下调）。⚠️ **改阈值会平移 Δx**（掩膜边缘缩/胀：同帧
  `thresh` 0→346px、8→376px）—— **先把阈值定死，再标 `road_dx_ideal`**，反过来白标；`road_dy_ideal`
  同理。
- ⚠️ **别再试"按帧间共识重挑块"这类补丁**（2026-09-30 写过一版，撤了）：掩膜碎成小岛时没有正确
  答案 —— 多数小岛占多数就**稳定锁在错块**，势均力敌时它把「分成两簇 → 明确不给数」悄悄变成"多数决"。处方是调阈值。
- ⚠️ **裁 ROI 底部 ≠ 让 Δy 有效**：裁底能把小车/雪弗板排出窗外，但黄区**常铺到画面底**，"下边缘"
  永远落在 ROI 线上 = 饱和 → `bit4=0` → 横向照样跳过（实测 ROI 下沿 0.72/0.60/0.55/0.45 四档 dy
  全被裁）。**Δy 能否用取决于"黄区下边缘是否落在窗内"，不是窗开多大**；旋钮是阈值。
- ⚠️ **实测Δx 变小 = 车走近**（黄区变大、左边缘往左），故 `ROAD_DX_DIR` 通常填 **−1**
  （`app_config.h` 默认即 −1）；现场按标定法确认。横向 `road_sign_y` 同理现场定。
- 指令 `"G"` / `RPI_TASK_ROAD = 20` / `RPI_ROAD_TAG 0x08` / `RPI_ROAD_LEN 12`。flags：bit0 边缘
  有效 / bit1 黄区贴画面**左边**（Δx 饱和） / bit2 贴上下边（只提示） / bit3 面积勉强 /
  **bit4 = Δy 有效（下边缘没被裁）**。⚠️ 长度 12（不是 9）；dx/ex/ey 是 **i16**（本协议唯一一条有符号坐标），**Δy 是 u16**。
- ⚠️ **单次开环**：一次只走一步、不死循环；**要迭代收敛就在 `map.c` 里连排两块**。⚠️ **它只动车、不碰舵机** → **不进 `c_bIsArmStep`**。
- ⚠️ **未标定（`ROAD_DX_IDEAL_PX = 0`，默认即 0）一步不动 + 失败音**，绝不照占位值动車；**但仍测量并把 `road_dx` 发到遥测**（日志 `ROAD fail: road_dx_ideal not calibrated (meas above)`）
  —— 故意如此（标定就是"读这个数"）。横向同理（读 `road_dy`）。
- ⚠️ **白平衡在 Pi 侧锁死（2026-10 加）**：看路用**固定 6500K**（Pi `config.py` 的 `ROAD_AUTO_WB=0` /
  `ROAD_WB_TEMPERATURE`；现值走 Pi Web「设置参数」存 `config_override.json`，**改完要重启 `gks.service`**）。
  本步按 **R−B 色度差**判定，而 **AWB 每次开相机从零收敛 ~2s**（R−B：第 1 帧 −47 → 第 15 帧 −14.5 →
  第 40 帧 +6.3）→ 冷开三次 Δx = **1297 / 192 / 192**（差 1100px），固定后 **192 / 192 / 192**。⚠️ **换场地/
  换灯后先调 `ROAD_WB_TEMPERATURE` → 再调 `ROAD_WARM_THRESH`** —— 顺序反了就是白标（阈值跟着平移）。
  ⚠️⚠️ **2026-10-07 主摄档（`CAM_MAIN_*`，色球/标靶/主摄扫码共用）也固定 6500K 了**（Pi `config.py`
  `CAM_MAIN_AUTO_WB=0`，备份 `config.py.bak-wbmain`）：现场证据 = 色球紧跟看路（固定 WB）之后跑，
  租约**就地换档**把 AWB 重新打开 → 5s 投票窗的前半段全落在 AWB 收敛期 → 画面色温逐帧漂（定格帧白纸
  偏黄）→ 绿球散布 87px / 蓝球 46px 超散布作废 → `三色齐备 1/3` → `BALL1 fail: scan`（07:17:30 那次，
  `color_0003.jpg`）。固定 6500 = 本机位 AWB 的收敛值，色球/靶标 HSV 阈值理论上不用动 —— 改完先跑
  一次色球识别验证三色齐再谈微调。**人质档（HOSTAGE_）仍是 AWB**：YOLO 对色温不敏感，暂不动。
  ⚠️ **2026-10-30 更新：看路档可以跑 AWB**（现场 `config_override.json` 现为 `ROAD_AUTO_WB=1`）——
  `_floor_gray_world` 每帧按**地面参考块**做灰世界归一，等价于"拿地面当白点"的软件 AWB：AWB 的
  **全局**色温平移被减掉，阈值/Δx 不再要求相机固定 6500K。前提 = 参考块必须落在**地面**（见下面
  「地面灰世界归一」的底部参考块）且 **CLIP_X 走固件的饱和救援**（`ROAD_RESCUE_MM`，不是判失败）。AWB **收敛期**仍可能有帧间漂（尤其冷开/
  换档后的前 1~2s），归一化只能减掉全局平移、消不掉篷布与地面的相对色度漂——投票/MAD 兜底；
  真在现场看到首帧漂，固定 6500K 仍是后备档。**同一套 `road_dx_ideal`/`road_dy_ideal` 必须在
  最终选定的 WB 档下标定**（换 AWB↔固定要复标）。
- 标定量 `ROAD_*`（`app_config.h`「看路」段）+ 蓝牙 Tab **「看路」组**（`road_*`）全是运行时量。**标定顺序**：⓪ 选 WB 档（AWB 或固定 6500K；同一套标定在同一档下做）→ ① 预览里黄框贴不贴边（调 `ROAD_PROC_SCALE` /
  `ROAD_ROI_*`）→ ② 调 `ROAD_WARM_THRESH` → ③ 车摆理想位读 `road_dx` 填 `road_dx_ideal` → ④ 前后
  各挪 ±50mm 看 `road_dx` 变大还变小 → 定 `road_sign` → ⑤ 再跑一步应显示 `skip`（已在死区内）。
  **要开横向再多两步**：⑥ 车**横向**挪 ±20mm 看 `road_dy` 变大还变小 → 定 `road_sign_y` → ⑦ 同位
  读 `road_dy` 填 `road_dy_ideal`。⚠️ 两把尺在**同一个**停车位标，但**比例/方向各自独立**（图像 x/y 的 mm/px 不同）。⚠️ **标横向时 `use_y` 留 0 最安全**：`road_dy` 遥测**不看 `use_y`
  就会发布**（帧里有 bit4 时），故"读理想值"这一步车一步都不横移；标好再把 `use_y` 改 1。
- **理想值有两条写法**（2026-09-30 加）：蓝牙 Tab「看路」组的 `road_dx_ideal` / `road_dy_ideal`；
  或 **`STEP_ROAD_SET_IDEAL`**（原语 `vRoadSetIdeal(dx_ideal, dy_ideal)`，两个 float 参数）——
  把理想值**写进路线**，**每条预设能带自己的一套**。⚠️ **两条写的是同一对量，谁后写谁生效**
  （易失，断电回宏）：现场蓝牙调过、之后路线又跑到那一步，以路线里的值为准。⚠️ **0 = 这一项不动**
  （0 是未标定哨兵，写进去会关掉那一轴）；要真关横向就用 `use_y=0`。⚠️ 它是
  **瞬时**积木（只写 Beam、不发串口、不动车），照规则第 4 条**没有 `_WAIT` 后缀**。⚠️ 它要排
  在 `STEP_ROAD_ALIGN_WAIT` 之前（后写的生效）。⚠️ 新积木要**重启控制台 + Ctrl+F5** 才出现。
- 遥测：`road_status` / `road_dx`、**`road_dy`**（与 Pi 日志 `Δx=` / `Δy=` 得对得上 —— 差 > 1px
  = 0x08 帧解析串位；**dy 尤其要看**，它用原先恒 0 的保留字段，串位会读出"合理"的错数）/
  `road_ex`、`road_ey` / `road_spread` / `road_flags`。调试串：
  `ROAD meas: edge=(..) fl=0x.. sp=..px` / `ROAD dx: meas=..px ideal=..px` / `ROAD y: meas=..px
  ideal=..px` / `ROAD fix: x.xmm(F/B/skip)` / `ROAD fixy: x.xmm(L/R/skip)` / `ROAD fail: ...`。

### 投票早停改滑动窗（2026-10-30 加，Pi 侧 `tasks/_road.py::run_road_detect`）

**现象**：一次完整路线里 12 次看路有 **5 次采满 9 帧**（每次多 ~0.6s），而 04:31 那次 7 次里只有 1 次。逐帧日志的 Δx：`[1112,1106,1106,1106,...]`、`[1176,1168,1168,...]`、`[1056,1062,1058,...]`、`[1248,1242,1242,...]` —— **第 1 帧偏 6~8px、后两帧完全一致**，而旧早停判的是「**全部**已采帧的极差 ≤ 5px」，只差 1~3px 卡在门外 → 拖到满帧。

**改法**：早停判据改成「**最近 `min_votes` 帧**的极差 ≤ `ROAD_OUTLIER_MIN_PX`」且要求**多攒一票**（`len(hits) > min_votes`）。开头一帧没坐稳不再拖住整步；「多一票」保证不是三帧碰巧同值；真双簇/车在动在窗里照旧表现为极差大、自动采满。**聚合口径一行未改**（全部 hits 仍过同一套双峰/MAD），早停点不同带来的 Δx 差 ≤ ~2px（远小于 7px 死区）。现场五组序列离线回放：9→4/4/4/7/6 帧。

⚠️ **另加「全程极差 ≤ `ROAD_MAX_SPREAD_PX` 才许早停」**（2026-10-30 同日补）：车没停稳时会出现"前几帧漂、最近几帧碰巧稳"。06:36:20 现场（`road_0007` 运动模糊）最近 3 帧极差 2px、全程 28px，只看滑动窗会在 7 帧收工，随后被最终散布闸（25px）判失败；加上这道后历史不干净就照旧采满，最终判据拿全部帧裁决（与改版前一致）。下次同机位 `G` 立刻成功（8 帧、dx=1148.2、散布 8）。

### 看路前车体沉淀（`ROAD_SETTLE_MS`，2026-10-30 加，**调参 Tab 可改**）

**要解决的问题**：车刚巡线停 / 刚转完弯时底盘还在晃，相机在运动中途取帧 → 画面运动模糊 + Δx 逐帧漂，Pi 的散布闸把整步判失败。现场 06:36:20（`road_0007`）：轮子拖影、最近 3 帧 2px 但全程 28px > 25px → 失败；**下一次 `G`（06:36:25）就成功**（8 帧、dx=1148.2、散布 8）。这不是检测算法的问题。

**做法**：`ucRpiRoadAlign` **最前面**（发 "G" 之前、关 OpenMV 灯之前）`vTaskDelay(ROAD_SETTLE_MS)`，两条分支（开/不开 OpenMV 灯）都吃到。**编译期**宏（`app_config.h`「看路」段，`@(0~2000)`，默认 **300ms**），「调参」Tab 自动出现「看路前沉淀」一项；改完需**重编译**。**0 = 不等**（等同加这一行之前）。

⚠️ 它与 `ROAD_LED_OFF_DELAY_MS`（400ms，关 OpenMV 灯后等自动曝光收敛）是**两段独立等待**：开灯下总前置 ≈ 300+400ms。嫌慢先调小本值，别动关灯那段（那是给 AE 收敛的，机理不同）。⚠️ 纯让出式等待、有界固定时长，不查中止位（中止点仍只在步骤边界，同 `STEP_DELAY`），不占积木 `I(0)` 超时预算（那个是发 "G" 之后才起算）。

⚠️ 早停**只是不再读帧**，不是提前下结论；`_road_yaw.py` 的同款早停未改（它的量更干净，没这个现象）。备份 `tasks/_road.py.bak-earlystop-20261030`。

### 地面灰世界归一（2026-10-28 加，Pi 侧 `tasks/_road.py::_floor_gray_world`）

**要解决的问题**：比赛场地灯偏暖 ⇒ **地面自己的 Y−B 就有 +13~+14**（旧场地 0~+2），黄区只有 +19~+31，反差 12 级；谷底法的"鞍点 ≤ 较矮峰 50%"正好卡在边界（实测 53%~60%），**同一静止画面会逐帧翻面**（存帧比对：地面/篷布 BGR 中位一致，不是曝光漂移）。翻到"没找到黄区峰"支路时，②「黄区即主峰」把地面主峰(+13)当成黄区 → 阈值 main−6=7 → 整个地面过阈 → 掩膜泛滥 75%~84% → 泛滥闸把帧全拒，4s 白跑（2026-10-28 05:11 run：8 次看路 4 次 0 命中；05:26 run：5 次里 3 次 0 命中；05:40 run 第 3 次先废 17 帧/2.6s 才凑够 3 票）。

**做法**：每帧从 ROI **左下**"必定是地面"的参考块（x 2%~22%、y **75%~95%**；2026-10-30 从 40~70% 挪下来）取三通道中位，按 `gain = max/med` 做灰世界归一后再算 Y−B。**阈值选择/候选打分代码一行不改**。⚠️ 为什么挪到底部：车贴近/斜看或 `ROI_BOTTOM` 调小时，40~70% 会落在**黄篷布**上（03:32 现场两帧：参考块 Y−B 比篷布还高，+8/+13 vs +6/+12）→ 归一化把篷布当白点洗掉 → 整帧"没有黄色区"；左下条带在两种机位都是地面。护栏：块太暗/过曝、块自己明显发黄（Y−B ≥ 40）、增益偏离 > **35%** → **跳过归一**（AWB 下地面可能偏紫、增益 18~20%，25% 会误跳过）。开关 `ROAD_WB_FLOOR_EN`（config 未登记时缺省 1；=0 与旧行为**逐字段一致**，回归验证过）；参考块位置等旋钮见 `_params()` 的 `ROAD_WB_FLOOR_*`（缺省值，不登记 config 也能跑）。

**左边缘截断交叉检查（2026-10-30 加）**：只在「黄区即主峰」档（车很近/黄区占大头）——该档阈值 = 主峰−6，会把篷布偏暗的左端裁掉，掩膜左缘看起来像"真边界"而实际黄区已延伸到 ROI 左外（03:32 实测主阈 32 时左缘 x=274，低 20 级时整块碰到 ROI 左边、面积 1.5 倍）。所以用同帧低 20 级再抠一次：主块中心落在的那个更大的块碰到 ROI 左边（`bx<=2`）且面积 ≥1.2× → 置 `CLIP_X`；`run_road_detect` 对它**立即以 status=1 放行**给固件的饱和救援（`ROAD_RESCUE_MM` 后退→重测一次；**不要求 3 票、饱和 dx 不进位移算式**）。⚠️ **别在 Pi 侧判失败/不计票**：固件只在 status=1 的帧上看 bit1，status=0 进不了救援分支（03:54 现场实测：9 帧全 CLIP_X 被排除 → 固件 `ROAD fail: wait st=0`，用户加的救援步距一次没触发）。正常「谷底/小黄区」档不走这条。

### Δx/Δy 饱和救援（2026-10-30 加，Pi + 固件两边配合）

**要解决的问题**：车冲过头时两把尺会**同时没数**——黄区铺满画面：左边缘出画面左缘（"横向全黄"，
Δx≈0，蓝牙遥测 `road_dx≈0`）+ 下边缘出 ROI 下沿（蓝牙遥测 `road_dy=0`，日志 `ROAD fixy: skip
(no y edge)`）。老行为里这两种帧一个是被 Pi 的 `ROAD_DX_MIN_PX` 闸门**整帧拒成失败**（固件只见
status=0，没机会自救）、一个是横向静默 skip——都只能靠操作员手动挪车。

**做法**（`ucRpiRoadAlignInner` 的「饱和救援」段 + `_road.py` 的 dx_min 闸门）：测到"尺子没数"
的帧 → **车体系开环后退 `road_rescue_mm`（代码缺省 100；现场可蓝牙调）→ 沉淀 `ROAD_RESCUE_SETTLE_MS`
（300ms）→ 重发 "G" 重测一次** → 拿新帧照常算位移：

- **触发**：① `flags bit1 (CLIPX)`——黄区贴画面左缘；② `use_y=1` 且 `bit4 (YEDGE)` 没置——下边缘
  被裁（`road_dy=0`）。两种都触发只退**一次**。
- **方向 = 车体后退**（= 用户说的"向画面左移"/"退"）：前进→左边缘往左跑，后退→左边缘往右移回
  画面。⚠️ **方向 = `road_sign`**（与正常位移同一条；`vChassisMoveCameraForward(fRescue*road_sign)`），
  **不能写死负值**——本车 `road_sign=+1` 时写死负值会朝篷布走（2026-10-30 04:04 实测：救援后
  dx 304→288，越救越近）。饱和帧的**值**不可信、不参与算式，但方向符号仍由标定确定；也**不叠加
  世界坐标系**（车体系开环，不碰世界航向/世界系平移）。
- **必须等运动停稳再重测**：`vChassisMoveCameraForward` 内部的 `fChassisMoveDelay` 只是**梯形曲线
  估时**，EMM 实际停稳/车身摇晃还要一点时间；不沉淀就重发 G，Pi 会在运动中途取帧 → 还是 CLIP_X
  （04:04 现场 40/100mm 两次都是"车没停稳就重测"，dx 只变 10~20px → `dx still clipped after
  rescue`）。沉淀量 `ROAD_RESCUE_SETTLE_MS`（缺省 300ms，编译期）。若还差一点就把 `road_rescue_mm`
  调到 150~250（本测试机位贴得很近，40 偏小）。
- **Pi 侧配合**：`dx < ROAD_DX_MIN_PX` 的帧**不再整帧判负**，带 `FLAG_CLIP_X` 强制放行（值原样
  保留；`dx > ROAD_DX_MAX_PX` 照旧判负=认错东西）。固件**绝不消费饱和值**：见 bit1 就救援或判
  失败。⚠️ 部署顺序**先烧新固件、再推 Pi 文件**（新固件见旗标就自救；老固件收到放行帧会拿饱和
  dx 算位移——钳位后 ±150mm 的瞎走）。备份 `tasks/_road.py.bak-rescue`。
- **逐帧 CLIP_X 提前放行（2026-10-30 加）**：`_detect_one` 因 `bx<=2` 或「黄区即主峰」低阈交叉
  检查置 `CLIP_X` 的帧，`run_road_detect` **第一帧就 return**（status=1、bit1、dx 原值保留；
  **不要求 3 票**，也不做 `dx_min/dx_max` 范围与散布闸）——饱和是"信号"不是"测量"，要尽快让
  固件退后重测。⚠️ 03:54 实测：旧逻辑把这 9 帧排除 → 固件 `ROAD fail: wait st=0`，救援一次
  没跑；改后 Pi 打 `看路第 N 帧: 左边缘出画（Δx 饱和），放行给固件救援`，固件进
  `ROAD rescue: dx clipped back XXmm`。⚠️ 部署顺序仍是**先新固件、再推 Pi**（老固件会把饱和
  dx 当测量）。
- **旋钮**：`road_rescue_mm`（蓝牙「看路」组当场可改，断电回 `ROAD_RESCUE_MM`）。**0=关闭**：
  Δy 被裁照旧只 skip（老行为），Δx 饱和帧直接判失败（老行为里这种帧被 Pi 拒掉，语义等同）。
- **单次、不循环**：退一段→重测一次；还饱和（`dx still clipped after rescue`）或重测失败 → 整步
  失败+失败音，要迭代路线连排。**标定态不救援**：`road_dx_ideal=0`（纵向没标）或 `road_dy_ideal=0`
  （横向没标）时不触发——标定全程零运动纪律不破。
- ⚠️ **超时预算**：重测用**整份** `timeout_ms`（I(0)），整步最坏 ≈ **2×超时 + 后退位移时间**——
  路线里这一步的超时要留够。救援与重测都在「临时关补光」包装内（灯全程灭，两次测量光照一致）。
- 调试串：`ROAD rescue: dx clipped|dy lost back XXmm` → 重测失败 `ROAD rescue fail: wait/link
  down/no left edge` → 还饱和 `ROAD fail: dx still clipped after rescue`。Pi 侧放行时打
  `[WARN] 看路: Δx=..px < 下限 .. —— 黄区贴画面左缘（Δx 饱和）, 带 CLIP_X 旗标放行`。
- **离线回归**（真机原始帧 A/B：改版 vs `_road.py.bak-rescue`）：健康帧 dx/dy/flags 逐字段一致
  （Δx=990 / Δy=562 / fl=0x15）；`dx_min` 强调到 3000 强制走新分支 → 新版带 `fl=0x17(CLIP_X)`
  成功放行、dx 原值保留，旧版照旧判负。

### ⚠️ 第一版为什么被换掉（别把「弯道角点」那套捡回来）

4. 把闸放宽能过，但**夹角只有 46°**（真实角该 >100°）—— **貌似有数、其实错的**，所以没放。

## 看路校准（`STEP_ROAD_YAW_WAIT` → `ucRpiRoadYaw`，2026-10 加）

**要解决的问题**：陀螺仪 yaw 会漂（零偏随温度/时间慢变），过弯/走直线全靠它咬航向，漂了
整条路线斜着走。本步给一个**世界基准的航向读数**：地面黄区（比赛黄胶带 / 练习图米黄篷布）
**固定在场上**、相机**固定在车上** ⇒ 黄区直边在**图像里的方向**只随**车航向**变（直线方向
对平移不敏感 —— 比看路那两把尺 Δx/Δy 干净：那两把尺把平移和航向混在一起）。

**链路**：路线排 `STEP_ROAD_YAW_WAIT` → `ucRpiRoadYaw` 发 `RPI_TASK_ROAD_YAW`（`"H"`，
`_MS_COMMANDS` 白名单内、互斥元组第 10 项）→ Pi `tasks/_road_yaw.py` 复用看路的 Y−B 自适应
掩膜，在 `ROADYAW_ROI_*` 子窗内对黄区直边做 Huber 直线拟合 → 回 **0x09 帧（8B：ang[0.01°]
+ cols + rms[0.1px] + spread[0.01°] + flags**，见 Pi 仓库 `docs/串口协议.md` §6j）→ 本端只发
遥测（`roadyaw_*`）与调试串（`ROADYAW meas:` / `ROADYAW err:`）。

- ⚠️⚠️ **每次跑都对齐到相机真值（2026-10-08 定稿，无 mode 槽，首次也不豁免）**：
  `bias = wrap180(原始航向 − err)` ⇒ 发布 yaw ≡ err —— **每次校准后全场航向零点 = "放直"方向**，
  上电摆放误差与累计漂移一次消掉（不响）。首次定标不限幅（初始对齐量合法地大），
  之后每拍限幅 `±ROADYAW_BIAS_MAX_DEG`(15°)：帧跳变超限 = 看错了，拒绝 + 保留旧偏置（不响, 留痕）。
- ⚠️ **世界坐标系不受校准影响**：`vChassisMoveWorld` 查表的 world_heading 由 app_pid
  记录时换算回**原始值**（`fPidWorldYaw`，app_pid.c）—— 跨校准记录/消费的「路径残留偏移」
  不会错轴。校准只劫持**闭环航向与显示**用的那个陀螺值。转弯 absolute 档/巡线陀螺腿的
  gyro_target 在校准后坐标系里教/排：路线开头（车摆正之后）先排一块看路校准，再教/排；
  之后到点各排一块持续对齐。
- ⚠️ **偏置怎么生效**：`app_sensors.c::vGyroPublishAttitude` 是全场**唯一**的工作航向出口，
  编译期 `ROADYAW_APPLY_EN`（默认 **1**）= 发布 yaw 统一扣 `roadyaw_bias` —— PID/巡线陀螺腿/
  支点转弯/OLED 一致受益。**现场不碰蓝牙，蓝牙只拿来调参数**；偏置上电=0，开着也无副作用。
  0 = 只算不扣（偏置照样进遥测，台架验证用）。
- ⚠️ 修正为何是"到点离散修"不是"连续互补"：修的时机 = 看路校准步骤（停车、无闭环），
  阶跃无害；慢速斜坡反而把修正摊进行车。**别硬置 yaw**、别在行车中修 —— 那才会踢到
  咬航向的闭环。
- ⚠️ 遥测两件套：`roadyaw_bias`(当前偏置) / `roadyaw_calib`(基准位记录的陀螺原始航向)。
  偏置/基准**易失**（上电归零 —— 漂移零点本来就该开机时建立）。
- ⚠️⚠️ **未标定哨兵是 |值|>90，不是 0**（`ROADYAW_ANGLE_IDEAL_DEG` 现默认 +90，999 只是"未标定"
  备用哨兵）：竖直的直边 ang 本来就 = 0°，0 是合法值。未标定 → 照测照报（不响 —— 校准流程静音）
  （同 `road_dx_ideal` 的"鸡生蛋"纪律）。
- ⚠️⚠️ **方向角是 mod 180° 的量（2026-10-08 台架实测踩坑）**：+89.9° 与 −89.9° 是同一个
  朝向（差 0.2°）。本机位篷布下边缘是**近水平**直边 = 贴着 ±90° 边界，画面再纯净、相邻两帧
  读数也会在 ±89.9 两侧跳 —— 投票直接拿原始读数会被判「两簇差 180°/散布 179.9° 超限」而失败
  （03:33 那次就是，**不是掩膜问题**）。Pi 侧投票已改圆均值（`0.5·atan2(⟨sin2θ⟩,⟨cos2θ⟩)`）
  折参考系；本端 err 也按 mod 180 折回（`ucRpiRoadYawInner` 的 `fmodf` 三行）。**遥测
  `roadyaw_ang` 在 ±90 两侧跳是正常的，看 `roadyaw_err`（连续量）**。
- ⚠️ **与巡线帧的 angle 不是同一个东西**（那是交界线图像倾角，被航向环直接消费），标定值
  别互相抄。
- ⚠️⚠️ **两个出厂标定值（2026-10-08 台架实测，别再瞎调）**：`roadyaw_ideal` = **+90°**
  （放直时直边近水平、屏显读 +90；±90 是 mod 180 同一朝向，err 有折回两种写法等价，按屏显写 90）；
  `roadyaw_dir` = **−1**（实测对应关系: **陀螺正漂/正转 → 相机读数减小** 90→88；陀螺负漂 →
  读数过 +90 边界翻到 −88 —— 后者是 mod 180 表示的正常现象, err 连续）。换机位/换边才需要
  蓝牙改。→ 路线**开头基准位排一块**（自动记陀螺基准），之后到点各排一块（校漂移），到点
  位姿尽量与首次相近。Pi 侧标定：`ROADYAW_ROI_*` 子窗**罩住一段直边**（别把拐角/圆弧
  罩进来；掩膜/阈值复用看路那套）。
- ⚠️ Pi 侧会**自动剔除贴窗边的轮廓点**（窗边框是车固连的直线，混进拟合 = 测到常数 —— 正是
  "拿车身当基准"那个死胡同的缩影）；窗被黄区填满时边界没穿过窗，报「边界点太少」→ 挪窗，
  别调门限。质量门：直段长 ≥ `ROADYAW_MIN_SPAN_PX`、RMS ≤ `ROADYAW_MAX_RMS_PX`、内点
  ≥ `ROADYAW_MIN_COLS`，投票与看路同一套（圆均值折参考系 → 双峰 → MAD → 均值，早停）；
  瞬态失败（散布超限等）**自动重采**，总轮数 `ROADYAW_ATTEMPTS`=3（双簇不重采，
  一轮 ~1.5s，路线超时建议 ≥6000）。
- ⚠️ 练习地图的黄区是**大圆弧**没有真直边：短窗拟合出的是切线方向，配合"固定停车位标定"
  仍可用；正赛黄胶带才是真直边。台架验证可贴一条直胶带。
- 部署顺序**先 Pi 后固件**：旧固件没有 0x09 分支 → 8B 帧被静默丢弃（不炸链路，步骤失败）。
  反过来新固件 + 旧 Pi 只是永远等不到帧，超时失败（不响），也不炸。

  可写）。Web 端 `GKS_Web` 指令按钮表已加 `"H"`，台架上可直接点着验证。
